# Canvas 断连恢复修复

2026-10-22。用户报告员工 Windows Web 工作台频繁提示画布不可用；原设备无法现场复现。本轮修复共享连接代码，并使用 Mac 与云端 Windows 隔离环境验证。源码自查不能证明原设备的唯一根因，也不把其他电脑的通过结果当成员工原设备复测。

## 已确认问题与修复

- 旧前端收到 SSE `hello` 就显示已连接，首次画布状态上报失败后不主动补报。现在必须等当前连接的最新快照上报成功才显示已连接；网络错误与临时 HTTP 错误采用有上限的退避间隔补报。
- 状态请求可能一直悬挂，阻塞后续同步。新增 10 秒超时和取消；退出页面时取消未完成的状态请求，旧异步回调不能把新连接标为成功。状态写入串行，避免旧快照晚到覆盖新快照。
- 旧前端不检查服务端心跳。现在监听心跳；前台 45 秒未收到心跳或 EventSource 已关闭时重建连接。浏览器仍在正常重连时由其处理；后台标签页不做心跳超时判定，恢复可见后给心跳恢复时间，避免后台节流误触发重连。
- 同一页面重连保持 clientId；服务端在替换连接前清除旧快照并结束旧 pending 请求。新连接必须重新上报快照，旧连接延迟关闭不能删除新连接。
- 工作台按任务保留窗口引用，重复点击复用已知窗口和在途打开请求，不重载正在使用的画布；不同任务仍分开。工作台刷新丢失窗口引用后，若服务确认已有连接，关闭预留空白页并提示已有连接，不继续制造重复画布。

连接恢复只补传画布状态，不重新执行绘图、图片工具或付费请求。原请求回执丢失时继续按结果未知处理，由既有任务状态核对流程确认结果。

## 验证范围

- Mac 本机：连接生命周期、窗口管理、真实浏览器故障注入、配置同步和局部改图共 31 项通过；Canvas bridge 16 项通过；Canvas TypeScript 检查通过。故障注入包含首次状态 503、连续三次关闭真实 SSE 流、重连时状态上报失败、切换标签页、工具已执行但回执丢失后断流。
- Mac 可见 Chromium 补测 9 项通过。完整 Node 回归为 333 项通过、2 项跳过：Windows PowerShell 专属检查，以及当前 Python 环境缺少锁定文档依赖的工作区文件工具检查。未将跳过项计为通过。
- 真实浏览器窗口测试使用不同 localhost 端口，验证移除 opener 后仍能复用 WindowProxy，同任务不重复开页、不重载，不同任务隔离、关闭后重开。
- 单元测试使用虚拟时钟验证心跳超时、后台节流、请求悬挂与超时取消；不将虚拟时钟结果写成真实电脑休眠验证。
- 云端工作流为 `.github/workflows/canvas-recovery.yml`，在 Windows 2025 与 macOS 14 原生 runner 构建并运行定向回归；Windows 新增浏览器测试使用可见 Chromium。实际运行与最终提交记录在验证后补充。
- 所有任务和账号配置均为临时夹具。图片配置回归使用本机模拟服务；断连回归阻断外网，包括无关的公共提示词目录检查。未调用真实员工账号、Teedy 或付费生图。

## 交付边界

本轮更新源码与回归，不改变旧候选安装包。原报错员工设备、操作系统实际休眠／唤醒、安全软件／代理干预及任意上游图片服务仍需按实际情况验证。不得仅凭“Canvas 未连接或不可用”的合并提示认定是用户没有保持画布前台。
