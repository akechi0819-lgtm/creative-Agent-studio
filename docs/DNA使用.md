# 轻量 DNA：默认关闭的全局创作提示词

2026-10-14 用户确认本期只做轻量全局提示词，不做品牌层级、自动记忆或偏好学习。配置默认不存在；`show` 返回关闭状态与空内容，不创建实际用户配置。

- 查看：`node scripts/dna.mjs show`。
- 可选示例：`node scripts/dna.mjs template`，不会自动保存或启用。
- 保存：`node scripts/dna.mjs save @payload.json`。内容为 `enabled`（布尔）、`content`（文本）、查看时的 `expectedRevision`、实际人工 `by` 与明确保存依据 `note`；开启时文本不得为空。首次查看返回 revision 1，第一次保存得到 revision 2。
- 关闭：保存 `enabled:false`，允许保留自己填写的文本，关闭后不作用于新任务。

保存采用写锁、原子 JSON 和必需版本比较，保留历史版本。版本过期先重新查看并核对修改，不机械更换 revision 重发。数据位于系统产品数据目录的 `dna/profile.json`，不在源码目录。它不是模型凭据配置文件。

新任务创建时保存当前有效 DNA 内容和版本，旧任务和旧制作单不会随全局保存变化。若用户明确要给已有任务应用新版，查看全局 DNA 与任务后执行：

`node scripts/studio.mjs apply-dna TASK_ID @payload.json`

payload 必须有 `dnaRevision` 和任务当前 `expectedRevision`。该操作更新任务输入，使输入、制作单、审核与最终批准失效；宿主重新展示有效需求／来源／DNA，取得人工确认后重新准备制作单。旧制作单中的 DNA 快照保留。关闭 DNA 后，已有任务也要显式应用关闭版本，不能声称它自动停用了旧任务规则。

宿主根据任务快照中的有效 DNA 整理需求、制作单和审核，显示本次覆盖或冲突；遇到任务临时要求与 DNA 矛盾，交由用户决定。DNA 不作用于素材清洗，不替代业务事实资料、来源筛选或人工批准。CLI 的 `by` 字段只是记录，不是授权或身份认证。

可选模板：

```text
表达语气：
视觉与品牌偏好：
常用内容要求：
必须出现的元素：
避免出现的元素：
其他偏好：
```

P2 提供共享工具与 Codex 操作；编辑框、保存与启用开关的完整 Web UI 在 P3 实施。模型连接和 macOS 安装不由此脚本承担。

异常退出留下写锁时，先核实 `dna/.write-lock` 中 PID 已退出，再用 `node scripts/dna.mjs unlock @payload.json` 显式提供同一 `deadPid`。进程仍在或锁信息不完整时拒绝清理。此操作不修改 DNA 内容。

Web现可点击“在当前任务停用 DNA”，显式应用已保存的关闭版；影响说明在按钮旁展示。该动作仍核对任务与DNA版本并失效下游确认，不删除全局草稿，也不静默更改其他任务。普通保存草稿无需再次弹同义确认；岗位包含AI的人工姓名可记录，但身份字符串本身不能代替用户明确同意。见 [修正记录](P3小范围修正与护栏精简.md)。
