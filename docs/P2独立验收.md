## 必须修复：清洗期间全局标签操作留下失效的清洗状态

位置：`src/assets/library.mjs` 中的 `cleanAsset`（约 812—845 行）、`recoverClean`（856—883 行）、`renameTag`（1094—1100 行）与 `deleteTag`（1120—1125 行）。

独立反例：暂存一个已有自由标签的素材，开始异步清洗并等待；在清洗完成前改名或删除该全局标签，再让清洗返回。两种操作均得到：

| 检查项 | 实际结果 |
| --- | --- |
| 原清洗返回 | `ERR_ASSET_CLEAN_STALE`，旧结果被拒绝 |
| 素材状态 | 仍为 `cleaning`，清洗 Job 未清除 |
| 直接重新清洗 | `ERR_ASSET_CLEAN_STATE` |
| 同一存活进程中 recover | `ERR_ASSET_CLEAN_OWNER_ALIVE` |

标签操作增加了素材 revision，但保留清洗状态；完成或失败回写发现版本冲突后直接退出，没有结束已失效的 Job。CLI 进程退出后可以显式恢复；常驻进程仍在时无法通过 recover 解除。额外人工编辑也可以解除，但这不是正常的失败重试，不能要求用户靠改内容解锁。

修复须保证：全局标签操作与在途清洗交错时，人工标签不被旧结果覆盖，素材不会遗留已结束的 `cleaning` Job，可通过正常路径重试；模型成功返回和模型失败返回都应覆盖。也可在写入前明确拒绝与清洗冲突的标签操作，但不得出现部分修改后卡住。增加对应合同反例，复验全量测试和原批次只读完整性；无须重新付费清洗或生图。

可重复的无网络夹具：[concurrency-repro.mjs](evidence/p2-independent/concurrency-repro.mjs)。运行 `node docs/evidence/p2-independent/concurrency-repro.mjs`，仅使用临时数据并自动清理。脚本当前断言缺陷存在，不能作为修复后的通过测试。

## DNA 的证据边界

当前设计由宿主 Agent 读取任务 DNA，整理需求、制作单和审核；技能与 `docs/DNA使用.md` 已写明。执行器传给 Canvas 的是制作单逐页提示及文案，没有把全部 DNA 原文再次拼入绘图提示。DNA 可能包含语气、内容与审核规则，原文也可能与本次临时需求冲突，因此不能仅凭执行器未重复拼接就认定代码违反当前合同。

本轮通过的是配置、快照与失效规则；没有新增启用 DNA 的真实创作案例，不能宣称完整视觉效果已经验收。P3 宿主接入时需展示本次有效 DNA、冲突处理及它如何体现在制作单和审核中，并验证实际调用链路。

## 阶段边界

P0/P1 既有验收不变。P2 素材库待上述修复与复验，DNA 的已验证共享能力按范围记录；完整素材管理与 DNA 编辑 Web UI 属于 P3 计划，不是本次缺陷。P3/P4 未获施工授权。原实施自验保留在 [P2验收](P2验收.md)，当前状态及模块图见 [工程进度](工程进度.md)。

`renameTag` 与 `deleteTag` 在同一库写锁内读取全部受影响素材，先检查任一素材正在清洗或仍有 Job，再刷新标签目录及逐条写入素材。如果有冲突，返回 `ERR_ASSET_TAG_CLEANING`，所有受影响素材和标签目录都保持原样；等清洗结束再重新查看并操作。该方案符合首次验收允许的“写入前整体拒绝”策略。
