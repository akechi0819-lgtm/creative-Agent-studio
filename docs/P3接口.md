## 服务边界

- Studio API 只监听 `127.0.0.1`。每个请求校验 loopback 来源、Host 和同源 Origin；不开放 CORS。浏览器写请求必须带同源 `Origin`。
- JSON 请求体有大小上限；素材文件只接受有数量和总大小上限的 multipart 导入。服务端只返回同源预览/下载路由，不返回磁盘绝对路径、Canvas bridge 地址或 token。
- 对任务的每项持久状态修改均使用核心 `expectedRevision` CAS。人工确认必须由用户发起；Agent 只能准备草稿、候选或审核建议。
- DSH `onEvent` 只接收可向用户显示的业务状态/工具事件；内部推理不入会话、Job、日志或 API 响应。错误消息使用安全摘要，原始模型/Canvas 异常不向浏览器回传。
- `createStudioServer({root, agent, canvas, readConfig, staticDir})` 返回尚未监听的 Node `http.Server`，并从 `web/dist` 提供构建文件；集成启动可用 `listenStudioServer`，只允许绑定 loopback。关闭时停止接收新请求、取消活动 Job 并调用 `canvas.stop()`。

所有成功 JSON 响应使用 `{...}`；错误为 `{error:{code,message,details?}}`。`details` 仅包括安全字段，例如期望和当前 revision。未定义字段不得用敏感内容填充。

## Canvas

| 方法与路径 | 请求 | 响应 / 效果 |
| --- | --- | --- |
| `POST /api/tasks/:id/canvas/open` | `{}` | 调用 `canvas.ensure(id)`；仅此响应短时返回一次性 `openUrl`，以及 `{projectId,clientConnected}`。URL 不包含 token 或 bridge 地址。 |
| `POST /api/tasks/:id/canvas-sync` | `{expectedRevision}` | 只读发现当前任务生成节点的直连图片候选，响应 `{task,candidates:[{page,nodeId,title,imageUrl,width,height,sha256,selected}]}`；不自动选图。 |
| `POST /api/tasks/:id/canvas-sync` | `{expectedRevision,version,selections:[{page,nodeId}]}` | 只接受该任务 Canvas 目标中的候选节点，逐页调用 `selectImage` 并返回 `{task,candidates}`。 |
| `GET /api/tasks/:id/canvas/candidates/:nodeId?version=…&page=…` | — | 由 Canvas manager 重新读取该任务节点的图片 Blob，以同源图片响应提供预览。 |

Canvas 候选只来自任务当前执行 `pages[].nodeId` 连接的图像输出。同步时核验任务绑定的 `projectId/webUrl/clientId`；断连、跨项目节点、节点缺失、当前图片哈希变化时拒绝复审、批准和导出。已落盘图片断连时可以预览，但状态不能标记为 fresh。`POST /api/tasks/:id/canvas/open` 才返回含一次性 bootstrap ticket 的 `openUrl`；该链接不得持久化、写入日志或通过 GET task/bootstrap 返回。

工作台在页面恢复可见或重新获得焦点时，先只读刷新任务；若任务已有成功图片且没有活动 Job，再以最新 `task.revision` 调用 `POST /api/tasks/:id/reconcile-canvas`。`ERR_TASK_BUSY`、`ERR_TASK_ENTRY_BUSY` 或 revision 冲突只提示稍后重读，不重放旧 revision。普通 Canvas selection UI 变化不构成失效；只按逐页 freshness 结果识别已改 Blob、原图节点缺失或候选集合改变。

## 制作单实际传图与配置更新

每页 `referenceImages:[{sourceId,fileOrder}]` 最多 12 张，必须来自本单与本页 `sourceIds` 指向的已保留来源。确认时保存来源快照；执行前验证路径、文件类型和 SHA-256。实际 Canvas 同时创建图片节点、图片到生成节点的连线与 composer 引用 token，进入 `/v1/images/edits`；不选择图片时使用 `/v1/images/generations`。完整制作单引用变更产生新版本并撤销旧确认；对话局部修改的受限授权、逐页继承与上传图分支见 [对话局部改图](P3对话局部改图.md)。

Canvas 状态接口会截短长文本与 Data URL。文本摘要带原始内容 `contentSha256`，恢复时据此核验完整文案；图片恢复通过 `canvas_read_image` 读取原始字节核验，避免把摘要误判为被修改。

模型配置版本经私有通道推送到运行中的任务 Canvas，更新内存会话。页面定时、恢复焦点和生成入口读取当前会话配置；已发出的请求不自动重发。图片请求走本机 `__studio/image-proxy` 同源入口，服务端只允许当前会话所配置的图片服务及 models/generations/edits 路径，使用会话密钥转发，不跟随重定向。代理不新增通用外网转发能力。成功 generations/edits JSON 的 `data[].url` 会进入当前 Cookie 会话的精确结果 URL 内存清单（最多 64 条、最长 1 小时），仅允许该会话 GET 下载这些原样 URL；支持签名查询参数，下载不发送 API 密钥、不跟随重定向，图片下载上限 10 分钟。Canvas 将完整目标 URL 编码为代理路径，下载后保存 Blob 并按原有任务回收流程交付。

## Job 与并发

`GET /api/jobs/:id` 返回 `{job:{id,taskId,kind,model?,status,createdAt,updatedAt,events,result?,error?}}`。状态为 `queued | running | succeeded | failed | cancelled`；事件为 `{seq,time,stage,level,message}`，仅保留业务进展，不保留隐藏推理、原始异常或配置。模型 Job 的 `model` 为该次实际冻结的安全模型 ID。聊天 Job 持久化 `requestId` 与请求内容 SHA-256 指纹，服务重启后重建索引；相同请求重发返回原 Job，不重复追加会话或调用 Agent。`DELETE /api/jobs/:id` 请求取消并传播 `AbortSignal`；收费请求已经提交时，取消不表示上游已撤销。

Job 会先等待已排队事件写完，再释放任务 entry 与资源保留；两项释放确认成功后，才持久化并对外公布本次 `succeeded`、`failed` 或 `cancelled` 结果，因此读到这些终态时，下一项任务写操作已可开始。释放无法确认时，Job 会以安全的 `ERR_JOB_RELEASE_FAILED` 失败结果收尾；该错误不代表租约已释放，调用方应刷新状态后再重试。

同一任务最多有一个会写任务状态的工作台请求/Job。并发请求返回 `409 ERR_TASK_BUSY`。Job 记录保存在数据根目录 `web/jobs/`，用户/助手可见消息和操作记录保存在任务自身 `web/`。进程重启时，旧 PID Job 标为中断，保留核心检查点；通过核心已验证的死进程锁清理机制恢复，不重复提交未知状态的生成请求。Job CAS 不因旧 UI 自动刷新；revision 冲突要求重新读取并由用户检查。

### DSH 点选追问与答案

助手会话消息可以带 `questions:[{id,question,options:[{id,label}],multiple?,allowOther?}]`。`studio_ask_questions` 只保存待答问题并发出 `questions` 事件，不确认需求或参考；问题组为 1–3 题，每题 2–6 个选项，默认单选且不允许其他文本。答案请求以 `answers.messageId` 指向任务会话中一条已保存的问题消息，并一次提交该组全部问题的 `{questionId,optionIds,otherText?}`。服务端校验问题归属、问题完整性与选项有效性；`multiple:true` 才允许多选，`allowOther:true` 才允许提交非空其他文本。含答案时，服务端根据已保存的问题选项生成规范化用户消息，不采信客户端摘要文本，并持久化答案和 `requestId`。同一 `requestId` 仍按现有合同幂等；同一问题组不能用另一 requestId 重复作答。用户作答只是对话输入，不代表任何人工确认。

### DSH 素材检索与候选

用户要求查找或列出历史素材候选时，Agent 必须实际调用 `studio_search_assets` 搜索已人工确认入库的素材；先传入单个短主题关键词，不要把受众、引流目标和风格拼成一个长精确短语。原始短语未命中时，运行时会按短词回退。底层共享查询仍按原有不区分大小写的子串规则匹配。工具会返回 `{query,hitCount,returnedCount,stagedCount,items}`：`hitCount` 是所选查询词匹配的去重素材总数，`returnedCount` 是展示条数，候选最多 5 条，`stagedCount` 是本次新增到任务的待选择数量。`items` 只包含 `id`、`revision`、限长 `title/summary`、有限 `tags`、来源的 `kind/platform/factBoundary`、`filesCount` 和最多 3 项文件预览名称/类型/顺序；不得输出本机路径、哈希、历史版本、确认快照或 OCR/提取原文。

有任务时，搜索结果会在工具调用中通过当前 `expectedRevision` CAS 追加为 `decision:'pending'` 的素材来源候选。重复检索已有素材只返回结果，不改任务 revision，也不覆盖已保留或已排除决定。新增候选不是人工保留；用户仍须在工作台逐项保留或排除。若新候选加入时已有需求/参考确认，核心会使旧确认失效，工具事件会报告命中、展示、新增待选择数量及确认失效情况。无命中返回 0 项并记录真实工具结果，不得声称已列出候选。后续任务上下文、读取任务结果及写入类工具返回值共用来源投影：pending 库素材只传递限长摘要和候选字段；用户保留后才附上受限正文，不传完整 OCR、文件路径、哈希或素材历史。制作单上下文只传最新版本及有界页面文案，不重复传入制作单内部保存的来源/OCR快照。

用户本次上传的 `current_attachment` 在 `pending` 状态也可用于同条聊天理解：非排除附件的提取文字最多每个文件 4,000 字符、每个任务合计 16,000 字符，并明确标注为未经用户确认的材料；排除附件不进入模型上下文。聊天视觉输入最多 12 张，每张提供不超过 128 KiB、1MP 的有损预览，总量不超过 1.5 MiB。按来源、文件顺序和原件 SHA 复用会话已有预览，避免续聊重复附图；超出范围如实提示未读。旧大图通过 DSH 官方 image/offload projection 从模型输入卸载，原始会话事件与任务原件保留；成品复审不使用该聊天低清预览。提取文字仅帮助讨论上传材料，不会自动保留来源或确认需求。

恢复包含超过 32,768 字符历史素材检索结果的 DSH 会话时，适配器会只替换仍处于模型可见 surface 上的对应 `tool/result` 内容，保留 tool message 身份与 call ID，并将真实命中数和最多 5 项候选投影保留在摘要中。旧事件仍保存在 append-only 会话日志，后续模型请求只看到替换后的有界结果；无法可靠解析的结果不改写。

## 依赖注入合同

服务端用既有核心函数完成任务、素材、DNA 和导出动作。`agent` 来自 DSH runtime：`chat({taskId,text,conversation,signal,onEvent,expectedRevision,model}) -> {text,task?}`、`review({taskId,page,signal,onEvent,expectedRevision,model,beforeRecordReview}) -> {text,task?}`、`organizeDna({text,signal,onEvent}) -> {content}`、`check({signal,kind})`。Chat/review 的 `model` 已由服务端在 Job 入队前冻结；runtime 用它覆盖本轮 DSH provider catalog 与 agent options，保留同一 provider 的地址和密钥，也保留原 chat session ID，以支持后续对话换模型。Canvas 由 `createCanvasManager({root,readConfig})` 注入，提供 `ensure/state/sync/assertFresh/candidateImage/executionOptions/stop`；`candidateImage` 只返回当前任务节点的图片字节，`executionOptions` 只供服务端执行器使用。图片配置连通检查由服务端用私有设置对 provider 发只读模型列表 GET，测试以本机 stub 隔离，不要求 Canvas manager 发外网请求。测试可注入无需网络的替身；正式服务不得自写推理循环替代 DSH runtime。

## 聊天式创建（2026-10-15）

Web 新建任务使用 `{title:首条描述自动生成,brief:{content:首条描述}}`，不预填 format/pageCount。可选附件复用现有 attachments 与 chat 接口及幂等 ID。制作单 pages 数量接受 1—5，含 2；其他确认、版本与执行规则不变。详见 [聊天式创建](P3聊天式创建.md)。

## 确认参考后继续（2026-10-15）

Web 使用既有接口顺序完成：如存在 pending 项，先经用户弹窗同意将未选项排除并 POST references；再以返回 revision 调用 confirm-inputs；最后使用最新 revision 与当前选择模型调用 chat，要求整理制作单且不得代确认或生图。已经确认输入时跳过确认写入。各步失败立即停止，不自动替换旧 revision 重发。新制作单版本出现时界面切换到制作单；单次请求锁避免双击重复继续。


## 对话中的 Canvas 机械工具

`studio_canvas_state` 与 `studio_canvas_operation` 为 DSH 注册工具，复用当前任务的聊天 Job，不新增任意 Canvas 命令透传 API。宿主固定任务、真实用户消息、调用标识与版本，工具参数仅包含具体操作及节点；当前枚举为 import／stitch／compose／crop／split／resample／move／resize。像素结果以任务机械制品记录和助手消息附件回传，布局操作没有图片附件。结果不自动入总库、替换制作单或批准成品。各功能实际能力及未接范围见 [Canvas 工具接入清单](P3Canvas工具接入清单.md)。


拼接 `stitch` 接受 `nodeIds`、`direction` 与可选 `gap`／`background`；合成 `compose` 接受底图 `nodeId` 和按顺序绘制的 `layers:[{nodeId,x,y,width,height,fit?,clear?,smoothing?}]`，矩形为原始像素坐标。`clear` 先清除完整目标矩形再填色，`contain` 默认保持比例，`nearest` 默认保持边缘。`import` 接受 `image:{sourceId,fileOrder}`，宿主验证当前任务附件／哈希并生成稳定 Canvas 节点；模型不能传图片 URL、base64 或路径。`studio_canvas_read_image({nodeId})` 通过宿主的私有 `canvasPreview` 读取真实图片，DSH 用有界标准图像块提供给模型，而非仅回传链接文字。

`studio_canvas_detect_regions({nodeId,kinds?})` 经私有 `canvasRegions` 宿主回调返回 `{nodeId,sha256,width,height,regions,truncated,totalDetected}`；类型为 `barcode/text/rectangle`，每项含置信度、原像素 `bounds` 与向外扩2像素的 `suggestedBounds`，最多100项。实现使用本机 macOS Vision／Swift，只传回几何信息，不传识别文字或条码载荷。宿主在同轮缓存源图哈希，并在后续机械操作提交前校验；模型无权提交或覆盖可信哈希。检测前后均回读源图，变化则拒绝。

## 2026-10-16 交互减负与关闭版 DNA
