## 最小运行代码与复查

```bash
npm ci
npm run prepare:p0
npm run canvas:start
npm run canvas:status
node scripts/canvas.mjs tool canvas_create_text_node '{"text":"P0 文本节点"}'
node scripts/canvas.mjs image NODE_ID OUTPUT.png
npm run canvas:stop
```

启动器只启动静态 Canvas 与绘图桥接。打开编辑页后，网页用 fragment 中的本实例连接参数自动连接，并立即清除 fragment 中的 token。CLI 不导入 DSH；未连接编辑页明确报错，不误连其他 Canvas。若同项目打开多个编辑页，共享 CLI 拒绝歧义，必须显式选 clientId。

实例连接信息在用户数据目录的 `canvas-instance.json`，权限 0600。不要打印其内容。测试可用 `STUDIO_DATA_DIR="$PWD/.p0-state/runtime"` 覆盖目录。测试脚本使用独立 Chrome 测试页，不操作用户已打开的浏览器。

复查命令：

```bash
npm test --prefix third_party/canvas/canvas-agent
npm run typecheck --prefix third_party/canvas/web
npm run build --prefix third_party/canvas/web
npm run verify:parser
# 下两项使用自己新实例，无收费生成
node scripts/verify-controls-p0.mjs

# 真实生成测试依赖已启动Canvas和已授权本机配置；不会把未知请求自动重放
STUDIO_DATA_DIR="$PWD/.p0-state/runtime" npm run verify:p0 -- --new-generation
```

DSH 验证准备还需 `npm ci --prefix adapters/dsh --ignore-scripts` 和 `npm run p0:client:build --prefix adapters/dsh`；Codex Canvas 路径不需要这两步。

`verify-canvas-p0.mjs` 默认仅查询当前实例持久记录中的既有生成节点；只有明确 `--new-generation` 才提交一张新的收费测试图。未知状态先查询，不自动重新提交。Canvas 画布和图片仍存于浏览器 IndexedDB，实例配置存于用户数据目录；两者尚未统一为任务事实源。同目录服务重启保留网页 Origin。当前真实生图测试通过浏览器刷新验证 IndexedDB 保留；独立 controls 另实测了浏览器与服务双重启后的文本节点恢复；这仍不等于完整应用恢复、跨入口接续或收费请求恢复合同，这些属于 P1/P4。

## 接口改造与工程决定

1. 采用固定 Canvas 源码切片，不用上游 `npx @latest`。DSH 使用固定 npm 依赖与官方插件扩展，不 fork 推理循环。HTTP/SSE 负责工具传递，不再承担推理、聊天或启动 Agent。
2. 纯工具协议为 v1，不保留旧 Codex 会话兼容字段。服务的项目、实例、Origin、端口、token 与数据目录由 launcher 注入。
3. `/api/tools` 要求显式 projectId 与 clientId；`/canvas/state|activate|result` 同样查归属。错误目标被拒绝，工具结果先完成实际状态上报后返回。
4. 上游紧凑快照会截断 metadata.content；图片还是浏览器 Blob。新增 `canvas_read_image`，由网页将真实 Blob 转成 data URL 返回，共享层保存文件；不从截图反推原图，也不把 blob URL 当本机文件路径。
5. 生图提交返回只意味着操作已排入浏览器，随后必须查 config 节点及输出连线、`generation_get_status`，直到 succeeded/failed。已提交后异常不盲目重放。
6. 共享层使用 Node 标准库，PDF 使用 PDF.js，PNG/JPEG 解码和生成保留 Canvas 成熟实现。未引入 Python、向量库、复杂编排或新业务数据库。
7. 安装方案选 macOS `.app` 封装内置 Node 运行时、固定依赖与静态 Canvas/DSH 资源，配置与任务数据分离；P0 验证的是目录运行，打包、签名、干净环境、Safari/Windows 均未验收。P4 必须验证 DSH 动态插件与客户端资源在包内的发现路径。

## 真实 DSH 驱动补验说明

最初的工程测试由脚本直接调用 `ctx.tools.execute`，只证明插件工具管线；它没有调用对话 API。经用户明确选择后，新增 `adapters/dsh/live-plugin.mjs` 与 `scripts/dsh-p0-live.mjs`，通过官方 `dsh-llm-pi-ai` 的 OpenAI completions 协议，由 `ctx.agents.create`、`agent.followup` 和 `whenIdle` 驱动真实 Agent 轮次。共享 Canvas 代码仍不导入任何推理循环。

模型凭据从用户指定文件的**客户端 API Key**取得；文件中管理面板密钥未用于公开 API。公开 models 查询已确认 `grok-4.7`。凭据只存项目忽略目录 `.p0-state/model-credentials.json`（0600），进程内以环境变量传给 DSH credentials，配置 patch 只存变量名，不存密钥。生图配置保持独立，仍为 GPT Image 2。

模型读图描述与主执行者已打开的原图核对：雪山、松树、岩石、湖面倒影、橙黄天空、青蓝绿和无文字均相符。模型称“日落”属于推断；生成指令是 sunrise，图片本身不能独立判定时间，不把该描述当作生产制作单审核通过。

这一次真实轮次已完成，但包装脚本随后错误检查旧 provider 字段而报失败。字段已修复；从本次已落盘的 DSH durable session 抽取 assistant/tool 记录并复读 Canvas 状态形成回执，没有重发模型请求。报告记录 1 次 Agent followup、2 条 assistant 消息、1 次标题模型事件；未测量 provider HTTP 总数，不能写成“只调用了一次 API”。
