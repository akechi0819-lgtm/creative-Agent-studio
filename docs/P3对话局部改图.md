# P3 对话局部改图

日期：2026-10-15。用户已明确批准：首次完整创作保留原确认链路；已有图片的细节修改由对话执行，不重走完整素材与制作单确认。属于 P3 试用修复，P4 未授权。

## 交互约定

“只修改第二页，第一、三页保留”是本次修改的直接授权。Agent 应执行指定范围，不重复追问已经明确的页码，不写一份全新待确认制作单。只有缺少必要信息时才针对缺失项点选追问。仅询问能力或讨论方案不触发绘图。

成品页可点击“对话修改第 N 页”预填输入框，再补充具体意见；也可直接输入修改要求。以该页当前成品为真实原图，需要统一画风时再加入指定页面作为风格参考。底图和风格参考都传原始图片字节，不用文字描述代替。外部上传的已有 AI 图片可作为局部编辑原图，不必先做完整创作确认；附件使用授权仅覆盖本次编辑，不自动保留为创作素材或入总库。

新图回收后展示在成品审核区；其他页面沿用原文件与对应审核。仅改过的页面需要重新审核，整套最终批准失效。修改失败时显示旧图，保留失败记录，未知请求不自动重复付费。支持恢复本页上一版，恢复不发起生图。

## 共享实现

`src/creative/page-edits.mjs` 为 Web／Codex 共用入口，复用原 Canvas 执行器与任务写锁、CAS、提交意图和回收逻辑。

派生版本 `sheet.kind='page-edit'` 保存原制作单和父版本、真实用户指令、修改页、原图／风格图哈希及有效文案。它不伪造 `sheetConfirmation`。共享 `isSheetAuthorized` 区分完整制作单确认与受限对话修改授权，Canvas、执行器、复审、批准和导出使用同一授权判断。

已有成品修改从任务内可用执行历史取基线，允许当前存在尚未确认的新草稿；不删除这些草稿，也不因为它们重做所有页面。原图引用经过任务目录、文件类型、哈希和实际执行记录校验。来源发生实质冲突时明确报告具体冲突。

上传图编辑有单独的附件证据和输入指纹，不把上传图伪装成已成功生成的成品，不补写输入确认或把 pending 来源自动改为 retained。完整新创作仍遵守原来源和制作单确认约束。

## Agent 与接口

Web 的聊天 Job 为 `studio_edit_pages` 注入共享修改回调。授权中的 requestId 和文本由服务端实际用户消息绑定；模型只能提交目标页、修改意见、准确文案和参考选择，不能伪造授权。同一轮只提交一次修改工具，一次可指定多页；重复 requestId 不重复收费。

已有成品参数：`{edits:[{page,instruction,copy?,stylePages?:[page]}]}`。

上传图参数：`{mode:'uploaded-images',edits:[{page,image:{sourceId,fileOrder},instruction,styleImages?:[{sourceId,fileOrder}],copy?}]}`。

`POST /api/tasks/:id/restore-page-edit` 接收 `{page,expectedRevision}`，仅恢复本页历史图片与文案，保留其他页。历史图片预览依任务、版本和页码读取，并核验原文件哈希。

Codex CLI：`edit-pages TASK_ID @payload.json` 接收 `expectedRevision`、`requestId`、用户原话 `instruction`、`edits` 和可选 `mode`；`restore-page TASK_ID @payload.json` 接收 `expectedRevision` 与 `page`。Codex 宿主须核对用户明确要求执行，不能把讨论方案当成授权；不启动 DSH。

## 2026-10-15 人工复测：Web 与 CLI 参数混用

用户原任务第 17 轮的 `studio_edit_pages` 调用把 CLI payload 的 `expectedRevision`、`requestId` 放到了 Web 工具根参数。Web 只接受 `mode` 与 `edits`，因此调用在参数检查时被拒绝，未进入绘图提交；这次失败不能归因为上游或修改文案。根因是 DSH 同时注入了完整 CLI Skill，使模型得到相互冲突的入口说明。

Web 改为加载 `adapters/dsh/creative-studio-web.md`，不再注入 CLI Skill；CLI 文档和共享核心保留。工具 schema 与执行校验都限制 Web 参数，版本与用户授权仍由宿主绑定。参数错误明确返回 `input_invalid`，允许修正尚未提交的参数；执行回调开始后同轮不重复提交。局部修改轮次不能用全量制作单兜底。Canvas 断连明确提示打开当前任务绘图页，聊天输入区也提供连接按钮。

旧任务及历史会话继续可用，不需要新建线程或确认无关的整单草稿。修复验证使用隔离副本和替身改图回调，不重跑用户真实图片；不能据此宣称上游编辑质量已验收。


本轮验证：全仓 **172/172** 测试通过，见 [测试日志](evidence/p3-page-edit-entry-fix/contract-tests.log)。复制原任务和原 DSH 会话，在私有临时目录中使用真实基础模型续接；模型仅向 `studio_edit_pages` 传 `edits`，只指定第二页，宿主替身回调恰好调用一次，确认恢复原会话而非新建，见 [旧会话续接回执](evidence/p3-page-edit-entry-fix/existing-session.json)。全套浏览器替身链路重跑 **18 项通过**；首次重跑在轮询上传改图 Job 时发生 `fetch failed`，第二次完整重跑通过，没有修改产品实现来规避。原任务 **46 文件未变**，见 [完整性回执](evidence/p3-page-edit-entry-fix/production-integrity.json)。本机工作台已重启加载修复；刷新 Web UI 并打开当前任务 Canvas 后，可在原对话继续局部修改，不必确认 v7 草稿。以上仍是实施自验，P3 独立验收和真实上游改图效果待复测。
