# 模型来源与裁剪

更新：2026-10-17。本文是两类API与来源限制的当前说明。来源适配已按P3源码／本机集成范围独立复验，P4与P5阶段状态见 [工程进度](工程进度.md)。模型列表、历史单次实测和真实账号能力分别解释；不将上游当前可用性写成保证。

## 两类模型 API

产品只保留两类模型 API：

| API | 用途 | 调用方 |
| --- | --- | --- |
| 基础 API | 独立 Studio 的 DSH 对话、工具调用、读图；Web 与 CLI 素材清洗 | DSH、素材清洗器 |
| 生图 API | Canvas 图片生成 | 当前任务绑定的 Canvas |

基础模型来源插件为基础 API 提供来源选择，不是第三类 API。Codex 推理继续由宿主 Codex 会话承担；Studio 的基础 API 只供 Studio 服务及显式调用的素材清洗等操作，不替换 Codex 推理模型。CLI 清洗从 Studio 私有配置读取基础 API，不再读取 `STUDIO_TEXT_*` 环境变量。

## 基础 API 来源与当前证据

| 来源 | 使用方式 | 当前证据与限制 |
| --- | --- | --- |
| OpenCode | 匿名来源，不要求用户粘贴 API Key | 可以读取到 9 个模型条目；实际 chat 请求返回 HTTP 502，原错误为 “OpenCode's free tier can only be used from within OpenCode. Download it at https://opencode.ai and keep building.” Studio 将标记该来源当前不可用并推荐 Kilo；不绕过该限制。 |
| Kilo | 匿名来源，不要求用户粘贴 API Key | 可以读取到 15 个模型条目。`dots-studio/dots-3-note-preview:free` 已完成一次简单 DSH 文本、工具往返和附图颜色识别检查；这只证明基础能力链路可用，不代表生产质量、稳定性或任何额度承诺。 |
| WorkBuddy 国内版 | 用户本人登录国内账号，模型 ID 使用 `buddy/` 前缀 | 本机浏览器检查确认使用前需本人登录；真实账号登录待用户本人完成。不得用他人账号或从其他客户端拷贝登录凭据。 |
| WorkBuddy 国际版 | 用户本人登录国际账号，模型 ID 使用 `workbuddy/` 前缀 | 本机浏览器检查确认使用前需本人登录；真实账号登录待用户本人完成。不得用他人账号或从其他客户端拷贝登录凭据。 |
| 自定义 API | 用户填写自己的服务地址、模型 ID 和凭据 | 原有自用 API 配置与调用方式保留。 |

设置页将自用 API 入口置顶，并在托管来源旁提供显眼的“使用自己的 API”入口，避免自定义服务被免费来源列表遮蔽。

平台提供的免费层、额度、速率、可用区域与在线时间都由平台决定，Studio 不保证额度，也不承诺免费服务长期可用。WorkBuddy 使用必须由用户本人登录。OpenCode 实测 chat 返回 HTTP 502 后，本轮没有继续尝试绕过上游客户端限制。

## 本机服务边界

来源适配器以本机伴随服务运行，只绑定 `127.0.0.1` 的动态端口，并使用本机随机 token。启动 Web 工作台时会启动插件；关闭工作台时会停止插件。CLI 按需启动同一个本机插件实例。用户选择 OpenCode 或 Kilo 时无需手贴免费来源密钥；WorkBuddy 则通过用户本人的登录流程使用账号额度。自定义 API 仍使用用户自己的配置。

来源适配器只供本机 Studio 进程与浏览器工作台受控使用，不提供公网监听，也不把本机 token 返回给普通工作台 API、任务、日志或导出。来源适配不会更改宿主 Codex 的模型配置。

## 上游与裁剪

模型来源运行时取自 [Ebony-Vinyl/dsh-our-free-model](https://github.com/Ebony-Vinyl/dsh-our-free-model)，固定在 [`2daf7625619bc3a93b97b84a896357b9edb1064f`](https://github.com/Ebony-Vinyl/dsh-our-free-model/tree/2daf7625619bc3a93b97b84a896357b9edb1064f)。项目内嵌副本位于 `third_party/our-free-model`，上游文件清单及哈希记录在该目录的 `UPSTREAM.json`；保留上游 MIT 许可证和版权声明，许可证副本位于 `third_party/our-free-model/LICENSE`。

free core 按传递依赖闭包保留 44 个 `src` 源文件；`UPSTREAM.json` manifest 共记录 46 个文件（含 `LICENSE` 与 `package.json`），其中包含被导入但不挂载的 `aggregate`、EAC 和 token-saver 助手。这些文件作为依赖闭包保留，不代表 Studio 注册或开放相应能力。主服务只注册 OpenCode、Kilo、WorkBuddy 国内版和国际版；不暴露 EAC 或其他账号来源、原管理台、自动签到、更新器和反馈入口，也不附带这些功能的账号凭据。裁剪针对产品入口和运行注册，不以物理删除每个依赖文件中的所有相关字符串为目标。

WorkBuddy 的 `upstream-business` 文件作为可核验构建输入保留；P4 公开分发前清除其中未使用的 Loomy 认证和 Gemini OAuth 固定常量，原始上游 SHA 与本地去除后的 SHA 分别记录在 `UPSTREAM.json`；实际运行使用 tree-shake 后仅含 buddy／workbuddy 来源的 runtime。该构建边界避免把上游其他账号与服务通道注册到 Studio。

上游固定版本之外的改动需另行对照和记录，不跟随上游 `latest`。

2026-10-21 公司 Windows 启动返修：在现有 WorkBuddy 构建变换中，给 Windows 登录浏览器的 `cmd` 子进程补 `windowsHide: true`。固定上游输入及其 SHA 保持不变，更新本地生成 runtime 的 SHA；只隐藏伴随进程控制台，不改变认证、账号或上游请求。
