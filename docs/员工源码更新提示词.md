# 员工源码更新提示词

将下面整段交给员工本机的代理宿主执行。公司版使用 `codex/company-edition`，不能切换到个人版 `main`。本次从源码运行，不要求重新制作安装包。

```text
请更新本机 Creative Agent Studio 公司版，并证明日常入口实际运行的是最新代码。不要只执行 git pull 就宣布完成。

先读取项目 AGENTS.md 与 docs/源码更新与运行核验.md。旧版没有这些文件时，先只读盘点现有安装、进程及数据目录，再从已核实的项目远端取得目标分支和更新说明。

1. 记录运行中的工作台、Canvas、模型插件的程序目录、版本与端口，检查桌面快捷方式及其工作目录。检查是否有在途任务；有则等待，不能强制中断或重放任务。
2. 确认公司数据目录以及 API 配置、任务、素材实际存放位置。正常停止本项目旧服务后，在仓库外做私有备份。不要打印密钥，不修改 API 设置，不把用户数据加入 Git。
3. 核对远端为本项目仓库和目标分支 codex/company-edition，fetch 并记录目标完整 SHA。保护本地修改和未跟踪资料，禁止 reset --hard、git clean 或无差别目录删除。旧目录若只是解压包，没有 .git，则在一个明确的新源码目录获取公司分支，不把旧包伪装成 Git 工作树。
4. 按项目启动说明准备环境和构建；必须使用更新后的启动器，任何依赖或构建失败都不能继续使用旧产物冒充成功。保持原 Company 数据目录，不创建一套空数据来冒充更新完成。
5. 启动新源码，运行项目 status 与 doctor。要求 running=true、identityMatches=true；运行中的 sourceIdentity 与 currentIdentity 的程序目录及 buildFingerprint 必须一致。将实际 gitCommit 与本次目标 SHA 核对，本地修改若造成差异须列明，不能隐去。
6. 检查原 API 配置和任务仍可读取，仅比较存在性和本机哈希，不输出内容。用隔离测试任务打开 Canvas、读取状态并完成无付费的导入/裁切检查，不重跑正式任务，不调用收费图片生成。
7. 清理旧入口：将日常快捷方式改指向新源码启动入口，随后从这个日常入口再启动并核对身份。确认旧程序进程均已退出。新版安装、启动和无付费功能检查通过后，删除已核实属于本项目的旧程序目录、旧快捷方式及旧下载包，用户端只留一个有效安装目录和一套入口，不归档可运行旧版本。删除前核实绝对路径、程序清单、用户资料、本地配置和符号链接；先移出用户原件和需保留的本地资料，禁止删除共享目录或沿符号链接删除目标。不要删除整个 AppData、配置目录、任务目录或必要的私有数据备份。新版本验证失败时不删旧程序，明确报告更新未完成。
8. 最后输出脱敏更新报告：目标 SHA、实际运行 SHA、程序目录、身份匹配结果、日常快捷方式目标、配置与任务保留情况、Canvas 检查结果、旧程序及旧入口删除清单、当前唯一有效安装目录。任何一项失败如实标记未完成，保留诊断编号及脱敏日志。不要输出实例 token、API Key、带凭据URL或用户原件。
```

“运行新版”与“原设备故障已修复”分别验收。即使身份匹配，画布检查失败仍属更新后功能未通过，不能用新建空任务、换端口或重试付费任务掩盖。
