## 现在如何准备

- 四组 npm 依赖独立检查：使用 npm 自带 Arborist 比对锁定依赖图和实际版本，验证必要入口、可执行文件及原生能力；没有准备账本也能验证认领。只有实际缺失或不匹配的那组运行 `npm ci`，不因 Node 补丁版本或业务源码变化重装。
- 五个构建独立记录相关输入和输出文件哈希。已有完整且不早于输入的产物可认领；源码变化或某个输出缺失只重建对应组件，原生 ESM 后端改动不触发无关前端构建。更新的 force 只强制重建产物。
- OCR 的解释器、锁定依赖、模型分别验证。允许项目私有虚拟环境使用现有 Python 3.12；优先复用已有 uv，缺失时保留固定版本下载路径。平台条件依赖交给 Python packaging 的 PEP 508 marker 处理，Mac 本轮适用 21 包，锁文件共 22 条。
- 分组成功立即记录，失败只保留未完成项待重试。构建和 OCR 准备结束再次核对实际输入，期间编辑不相关后端不使全局准备失效，相关输入变化则不误写 ready。原有在线实例检查与准备锁保留。

新建虚拟环境先在 staging 中使用 [uv 官方 relocatable 模式](https://docs.astral.sh/uv/reference/cli/#uv-venv--relocatable)准备，检查导入、包版本和入口脚本后切换；旧环境不直接删除。模型预热失败保留已验证的运行时和包，下次只预热。helper 或业务代码变化不会删除环境。
