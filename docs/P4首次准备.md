# P4 首次准备与双平台入口

P4 的首次准备由 `src/launcher/prepare.mjs` 的 `prepareWorkspace()` 执行。它按根项目、Canvas Agent、Canvas Web、DSH 的锁文件运行 `npm ci`，再构建 Studio Web、两个 Canvas 组件、DSH 客户端和 WorkBuddy 来源插件。插件目录没有独立 `package.json` 依赖清单或锁文件，使用根项目锁定的 esbuild 构建。

准备状态保存在项目私有的 `.studio-runtime/prepare-state.json`。状态记录依赖清单指纹、Node 版本和完成状态；只有所有安装目录及必要产物存在、且指纹相同时，普通启动才跳过准备。`prepareWorkspace({ force: true })` 用于更新或显式强制重建。准备开始时先写入 `preparing`，失败时写入 `failed`，下次启动会重试；只有所有构建产物检查通过后才写入 `ready`。

`Start.command` 和 `Start.cmd` 是平台薄入口，参数原样转发给 `scripts/launcher.mjs`，无参数时传入 `menu`。macOS 支持 Apple Silicon 与 Intel；Windows 支持 x64 与 ARM64。系统 Node.js 满足项目要求（22.19+ 的 22.x，或 24+）且可找到 npm 时优先复用。否则 bootstrap 在 `.studio-runtime/node/` 下载固定的官方 Node.js v22.23.3 归档，不改系统 PATH、不进行全局安装。其他平台会明确报错。

指纹覆盖四组 package.json/lock、构建脚本，以及 `src`、Studio Web、Canvas Web、Canvas Agent、DSH adapter、WorkBuddy 插件构建输入源码目录，不依赖 Git checkout 才能检测代码变化。`.studio-runtime/prepare.lock` 串行化不同数据目录的准备；构建前扫描 `.studio-runtime/servers/*.json`。指纹未变时可复用在线服务的现有构建；确需重建时若任一服务进程仍运行，会停止并提示先停服务，避免覆盖正在服务的同一源码目录。

首次准备还会在项目私有目录安装固定版本的 uv 与 Python 3.12.15，按带哈希锁文件准备 RapidOCR 依赖，并预热模型到 `.studio-runtime/rapidocr-models/`。Python 虚拟环境位于项目 `.venv-ocr/`，不会安装或修改系统 Python；OCR 依赖、锁文件与 helper 也纳入准备指纹。

维护菜单生成的数据备份包含 Studio 本地配置、任务数据和 Canvas 服务端存储，并会标记 `canvasStorageIncluded: true`、`browserProfileIncluded: false`。旧版浏览器 IndexedDB 与浏览器个人 profile 不迁移；浏览器设置/缓存不属于项目数据备份。
