# P4 首次准备与双平台入口

准备流程由 `src/launcher/prepare.mjs` 执行，依赖安装、构建和 OCR 分别验证、分别保存状态。没有旧 ready 记录的开发目录先检查实际文件，不会直接执行四次 `npm ci`。

- 依赖：按根项目、Canvas Agent、Canvas Web、DSH 四组检查现有安装图、锁定版本、必要入口与少数原生能力。合格即认领；缺失或不匹配时只对该组运行 `npm ci`。Node 补丁变化只重新验证，不按版本字符串强制重装。
- 构建：按 Studio Web、Canvas Agent、Canvas Web、DSH 客户端、WorkBuddy 插件分别记录真实输入和全部输出文件哈希。无记录时只有完整、且不早于相关输入的产物才认领；否则只重建该组件。后端原生 ESM 代码变化不触发无关前端重建，源码变化不触发依赖安装。
- OCR：项目虚拟环境、锁定包、模型预热分别检查；优先复用现有合格 Python 3.12 与 uv。缺什么补什么，不因业务代码或 OCR helper 改动删除虚拟环境。平台条件依赖按 PEP 508 marker 判断。无模型记录时以实际空白／文字样例认领已有模型，后续校验模型哈希。

`.studio-runtime/prepare-state.json` 保存分组账本，阶段成功立即落盘；失败保留已成功项，下次只修未就绪部分。输入在实际操作前后及收尾再次核对；相关源码仍被编辑时不把不确定产物标 ready，无关后端编辑不使整套状态失效。更新传入的 `force: true` 只强制重建产物，不重装验证合格的依赖或 OCR。

`Start.command` 和 `Start.cmd` 是平台薄入口，参数原样转发给 `scripts/launcher.mjs`，无参数时传入 `menu`。macOS 支持 Apple Silicon 与 Intel；Windows 支持 x64 与 ARM64。系统 Node.js 满足项目要求（22.19+ 的 22.x，或 24+）且可找到 npm 时优先复用。否则 bootstrap 在 `.studio-runtime/node/` 下载固定的官方 Node.js v22.23.3 归档，不改系统 PATH、不进行全局安装。其他平台会明确报错。

构建输入按对应构建脚本实际消费的目录划分，运行日志、Node 补丁版本和无关业务后端不纳入构建失效条件。`.studio-runtime/prepare.lock` 串行化同一源码目录的准备；实际需要改动安装环境或产物时才检查 `.studio-runtime/servers/*.json`，防止覆盖正在服务的构建。只读验证与复用可继续进行。

OCR 始终使用项目 `.venv-ocr`，不修改系统 Python 包。已有 Python 3.12 和支持所需命令的 uv 可复用；缺失时仍自动下载固定 uv 0.12.24／Python 3.12.15。使用真实版本和依赖导入检查，不要求现有解释器的补丁号与下载默认值相同。新环境先在私有 staging 目录中准备并验证，使用 uv 的 relocatable 模式；通过后才切换，原有不可用环境另存。模型失败不会丢弃已经通过检查的解释器和包，也不会重复安装它们。

本次重复安装问题、隔离证据和真实目录恢复边界见 [启动准备复用修正](启动准备复用修正.md)。

维护菜单生成的数据备份包含 Studio 本地配置、任务数据和 Canvas 服务端存储，并会标记 `canvasStorageIncluded: true`、`browserProfileIncluded: false`。旧版浏览器 IndexedDB 与浏览器个人 profile 不迁移；浏览器设置/缓存不属于项目数据备份。
