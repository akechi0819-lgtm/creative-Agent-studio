# Company Lite WorkBuddy 使用

WorkBuddy 主界面承担安装、配置、创作对话和用户确认。本机 Canvas/MCP 是跨 WorkBuddy 线程共享的持续工作空间，保留历史项目、图片、排版状态和绘图连接；线程本身承载当前需求、材料用途、制作单、审核与批准，不建立独立任务或审批系统。

## 安装状态与操作

在 WorkBuddy 本地任务中选择 Company Lite 根目录，并显式要求读取 README、AGENTS、本文和创作 Skill。员工包用 `Start.cmd`／`./Start.command` 调用包内 Node；源码开发可直接运行 `node scripts/setup.mjs ...`。仅首次安装、配置或故障修复时简洁展示五项真实状态；日常创作不重复安装清单：

1. Company Lite 包和运行依赖就绪。
2. Canvas 组件就绪，且 WorkBuddy 实际调用本地 MCP 工具 `canvas_status` 成功。这个探测无需打开浏览器或生成图片，会自动记录不含密钥的检查时间。
3. WorkBuddy 使用公司现有 Teedy 只读 MCP 完成真实工具探测，并记录工具名。安装包只读取宿主报告，不独立验证员工账号。
4. 本机图片 API 配置 revision 已保存，并且同一 revision 的 `check-image` 连接检查通过；这不证明真实出图成功。
5. 全部必需步骤的总体状态。

Agent 自动推进已有可执行检查；仅在需要员工本人登录、通过 WorkBuddy UI 添加 MCP、复制图片 API Key 或 WorkBuddy 宿主审批时等待，不增加逐步确认。

如第 2 步等待 Canvas MCP：

1. 运行 `Studio.cmd mcp-config` 或 `./Studio.command mcp-config`，取得只含包内 Node 命令与 MCP 脚本路径的标准 stdio 配置；其中不含密钥或令牌。
2. 在 WorkBuddy 官方 MCP 页面“插件 → MCP 服务器 → 配置 MCP”添加这段配置。
3. 在 WorkBuddy 中实际调用 `canvas_status`；它返回本机共享 Canvas 服务的真实运行与连接状态，并写入不含密钥的 MCP 检查记录，不打开浏览器或生成图片。

使用 WorkBuddy 的可视化 MCP 页面，不自动猜测或写入其配置路径。[WorkBuddy MCP 说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)

常用本机命令：

- `Start.cmd status`／`./Start.command status`：读取五步状态。
- `Start.cmd report-workbuddy connected <工具名>` 或 `failed [工具名]`：仅在 WorkBuddy 已实际调用公司只读 Teedy MCP 后记录结果。
- `Start.cmd configure-image @image-config.json --key-from-clipboard`：在员工明确说“已复制”后读取本机剪贴板一次并保存图片 API 配置。
- `Start.cmd configure-image @私有JSON文件`：管理员已有本机私有配置时使用。
- `Start.cmd check-image`：检查 API 连通，不发起生图请求。
- `Studio.cmd status`／`start`／`open @JSON`／`stop`／`mcp-config`：管理本机共享 Canvas 服务。`open` JSON 可含 `mode`（`recent`、`new`、`choose`）或已有 `projectId`。

正式员工包使用包内 Node；不要求安装 Git、npm、Python、Office 或编译器。包装器与目标设备体验待验证。Canvas 是本产品唯一浏览器界面；不存在单独设置网页。

## 图片 API 与 Key

优先使用剪贴板输入，避免在 WorkBuddy 对话传递密钥：

1. 员工在图片服务页面复制本次 API Key。
2. 员工在当前 WorkBuddy 对话明确说“已复制”。
3. Agent 在能力包根目录准备不含 Key 的 `image-config.json`，字段为 `expectedRevision`、`image.baseUrl` 和 `image.model`，然后运行 `Start.cmd configure-image @image-config.json --key-from-clipboard`。
4. 命令仅读取一次系统剪贴板，把 Key 存入本机私有配置；不得回显、写入日志或再次读取。
5. 调用 `Start.cmd check-image` 查看同配置 revision 的连接结果；该命令不触发生图。

在员工明确复制并报告前，不读取剪贴板。Windows 剪贴板读取和员工包仍待目标设备验证。若使用含 Key 的已有私有 JSON，只能将它保存在本机受限目录；不得放入仓库、对话或普通命令参数。

## Canvas 与 WorkBuddy 线程

- WorkBuddy 对话线程是当前工作的唯一上下文。品牌要求、材料来源与用途、文案、制作单、用户确认、读图审核和批准都留在该线程。
- Canvas 跨线程共享，可按当前用户意图新建项目或找回、继续历史项目。旧项目的文案、来源、确认和批准不自动沿用到当前线程。
- WorkBuddy 通过 `canvas_open` 选择 `recent`、`new`、`choose` 或一个明确的历史 `projectId`。该选择打开共享 Canvas，不建立 task ID 绑定。
- Teedy 候选先由用户选择；作为参考前必须经公司现有云端 Teedy MCP 实际下载。搜索摘要和 URL 不是原件。只有下载后的原件才可通过 `canvas_import_file` 加入当前画布。保持 Teedy 内容、标签和 ACL 不变。
- 只有用户确认当前制作单并明确授权收费出图后，才调用 `canvas_run_generation`。它快速返回 `{submitted, nodeId}`，出图继续异步运行；之后用 `generation_get_status` 查询该 node。状态未知时先查状态，不重复提交收费请求。失败信息在 Canvas 节点状态中读取；重试必须由用户在当前 WorkBuddy 线程再次明确授权。
- 使用 `canvas_read_image` 返回的实际图片内容进行读图，检查文案、移动端可读性、品牌表达、主题与修改位置。缩略图或生成状态不是实际读图。修改后重新读图。
- 当前 WorkBuddy 线程中的成品经用户查看并明确批准后，才调用 `canvas_save_image` 导出。
- 既有操作包括图片导入、拼贴、拼接、组合、裁切、分割、像素重采样、移动和缩放。它们不是新增功能，也不替代 Canvas 的手动绘图操作。

一次本地 Canvas MCP 真实图片生成已成功：上游 API HTTP 200，单次请求耗时 20.198 秒，本地完整保存耗时 25.892 秒，准备画布耗时 1.051 秒；主代理已实际打开检查验收图，图像内容正确且没有生成文字。该单次样本不是通用延迟承诺，也不证明员工宿主流程已通过。

## WorkBuddy 工作目录与 Skill

WorkBuddy 本地任务的工作目录与 Skill 选择是分开的：先选 Company Lite 根目录，再用首次提示词显式读取项目规则和 Skill。官方[本地任务说明](https://intl.cloud.tencent.com/zh/document/product/1316/84504)列出工作目录与技能选择；官方[技能说明](https://intl.cloud.tencent.com/zh/document/product/1316/84503)支持上传本地 Skill，并说明可有项目专属 Skill，但没有公布项目目录的精确名称。

本项目不假设 `.agents/skills` 会被自动发现，也不复制到未经验证的目录。若从 Skills 页面上传 Skill，命令仍从员工为当前 WorkBuddy 任务选定的 Company Lite 根目录执行，不从 Skill 安装目录向上猜项目根。
