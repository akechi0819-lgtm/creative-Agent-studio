## 4. 未完成项是否必要

| 项目 | 是否需要 | 处理阶段 |
| --- | --- | --- |
| 重复真实触发 Canvas 已有的所有服务端错误、超时、网络失败 | 不需要为 P0 专门重做；复用成熟实现 | 只有上游行为或调用方式改变时才做针对性复验 |
| Canvas 报错后，共享连接／DSH 是否收到失败，任务是否停在正确状态 | 需要，属于我们新增的集成责任 | P1 任务执行合同；用可控错误模拟 |
| 工具请求发出后的取消、超时和迟到结果 | 需要；当前不是只缺证据，共享客户端也未接收并传递 AbortSignal | P1 执行合同；用可控延迟与取消模拟 |
| DSH 对话请求在途取消、模型服务失败后的界面反馈 | 需要，不阻塞本次框架可行性验收 | P3；使用模拟端点／适配器，不要求真实收费调用反复失败 |
| 已提交图片生成能否真正撤销 | 需要定义真实能力；不能保证上游已接受的请求可取消 | P1/P3 区分“停止等待”和“撤销上游生成”，不自动重放 |
| 中文海报文字准确性、多页一致性、制作单确认、换图复审与导出 | 需要；尚不属于 P0 | P1 至 P4，按完整首版矩阵验收 |
| 素材管理、OCR、复杂 PDF | 需要在支持范围内完成，不是本次框架技术验证 | P2 |
| macOS 安装、签名需求、干净环境和完整恢复 | 需要按实际交付形式验证 | P4 |
| Windows／Safari 的完整实机覆盖 | Windows 正式交付未纳入首版；浏览器支持范围在产品集成与打包时确定 | 不扩成 P0 阻塞项 |

“提交前已取消”只证明未发送操作，不能证明取消了正在进行的操作。当前 `adapters/dsh/live-plugin.mjs` 只在执行入口检查 `exec.signal.aborted`，`src/canvas/client.mjs` 未将信号传给 HTTP 请求。后续应补齐新增连接合同，而非重写 Canvas 的错误处理。
