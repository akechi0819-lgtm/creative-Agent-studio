# P4 跨平台区域检测

P4 用本地 npm 运行时替换了区域检测中的 Swift／macOS Vision 依赖。`detectImageRegions({bytes,mimeType,kinds,signal})` 接口和 Canvas 宿主校验不变；检测只返回原图坐标、区域种类和置信度，不返回识别文字或二维码载荷。PNG、JPEG 在 Windows、macOS、Linux 使用同一实现；没有 Swift 或平台回退路径。

当前实现组合为 `@napi-rs/canvas` 解码光栅图、`@techstark/opencv-js` 定位二维码和四角矩形、`tesseract.js` 输出英文与简体中文文字行几何框。两种 Tesseract best-int 模型作为 npm 锁定依赖随包安装，调用时复制到临时目录，不从网络下载模型。OCR worker 全局串行、关闭识别日志，最多运行 60 秒；每次结束或取消后终止 worker 并清理模型临时目录。原始图片仅在内存中解码。

透明 PNG 在检测用光栅上先合成白色背景，再交给二维码、OCR 和矩形检测，避免透明静区的 RGB 被误当成黑底。该策略不覆盖或重编码输入文件，原始透明度和像素仍由现有 Canvas 路径保留。OpenCV 加载后及返回结果前检查取消状态；不宣称可在同步图像计算中立即中断。相关返工证据见 [P4返工与自验证](P4返工与自验证.md)。

选型依据是离线可安装、Node 与 Windows／macOS／Linux 共用同一路径，并且能分别提供 OCR 行框和多二维码几何框。`jsQR` 仅作为夹具与 Canvas 合成结果的独立二维码解码器；它不是区域检测器，也不替代 OpenCV 定位。纯像素连通域不能证明文字语义，因此没有用它替代 OCR。旧 Vision 路径依赖 macOS，已删除；这次没有对其他 OCR 引擎做同一夹具的性能横评，不将其写成已验证的相对优势。

`barcode` 是现存 API 中的枚举名；P4 实际只识别二维码，不支持一维条码。检测前会对小图执行最近邻 2 倍二维码补充扫描，主要补足天然像素较少的模块图。矩形检测只接受内部区域内、凸四角且填充比例足够的轮廓。文字行框来自 OCR；实现还要求行置信度至少 65、至少两个可信词，使用像素对比收紧 OCR 框。短单词、低对比、装饰字体、文字竖排或大量纹理上的 OCR 结果不保证召回。

## 固定夹具和验收门槛

回归入口：

```sh
node --test tests/image-regions.test.mjs
```

静态合成的 `tests/fixtures/image-regions/poster-mixed.png` 含简体中文、英文、16–34 px 多字号文字、两块浅色底、内嵌文字矩形和二维码；`poster-mixed.truth.json` 保存绘制时的区域 ground truth。测试从这张 PNG 再编码 JPEG，不需要目标机器安装中文字体。风景和不规则纹理负例同样是静态 PNG。测试不读取真实素材。

在选择方案前，预设并逐项核对以下门槛：

| 能力 | 验收门槛 | 当前隔离夹具结果 |
| --- | --- | --- |
| 中英文文字行 | 匹配框 IoU ≥ 0.50；precision、recall 各 ≥ 0.90 | PNG 与 JPEG 各 6/6 行匹配，P/R 均为 1.00；最小 IoU 分别为 0.760、0.880 |
| 二维码位置 | IoU ≥ 0.90；各正例恰好一个框 | 2、3、6 像素／模块及 17° 旋转四例 IoU 分别为 1.000、0.974、0.987、0.984，均恰好一个框 |
| 透明 PNG 二维码 | 同码透明／白底均恰好一个框，检测框间 IoU ≥ 0.95；输入 SHA-256 不变 | 白底图经独立 jsQR 解码有效；两版均通过定位与字节不变断言 |
| 多二维码 | 两个码各 IoU ≥ 0.90，且恰好返回两个框 | 一个普通码和一个 21° 旋转码 IoU 为 0.969、0.982，恰好返回两个框 |
| 矩形 | 正例 IoU ≥ 0.80，恰好一个框 | 含中英文文字的描边矩形 IoU 1.000，恰好一个框 |
| 负例 | 风景和不规则纹理中的二维码、文本、矩形均为零框 | 两张负例均零误检 |
| QR 替换像素合同 | 先独立核对定位框；目标框外像素完全不变；新码由独立解码器读出 | 定位框 IoU ≥ 0.90，框外变化像素数为 0，`jsQR` 读出新载荷 |

本页二维码替换用例是**纯合成夹具像素实验**，只验证几何定位、检测框外像素保留和二维码可读性。它没有做复杂背景补绘；被覆盖的目标框内若是纹理或文字，仍可能留下明显覆盖痕迹，不能称为复杂背景无痕修复。实际 Canvas 浏览器 compose 合同由 `scripts/p4-qr-browser.mjs` 在独立服务验证中检查；不能用本夹具结果代替该产品路径验证。

## 输入上限和已知边界

- 接受 PNG、JPEG，压缩文件最多 20 MiB；最长边最多 32,768 px，最多 64 MP。超限或其他格式会明确报错。
- 最大 4,096 px 边长、12 MP 的分析光栅用于定位；结果映射回原始像素坐标。小于 1,800 px 且不超过 4 MP 的图像会额外做 2 倍二维码扫描。
- 文字模型只有英文和简体中文。测试证明的是本页固定合成夹具，不代表任意语言、字体、照片文字或复杂海报都达到同样召回率。
- 矩形定位是几何启发式，不是版面理解；圆角框、断线框、倾斜透视框、边缘贴合图像的框可能漏检，偶发高对比四角物体也可能形成候选框。
- 尚未据此验证 Windows 真机双击流程；跨平台代码回归与 Windows Actions runner 结果需分开记录。
