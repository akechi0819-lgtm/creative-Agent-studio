## 设计取舍

沿用现有鲸鱼助手、双栏工作台、字体与色彩。左栏以自然对话和必要的短方案卡为主，右栏直接展示方案、成品、对照与下载。根据用户现场反馈，删除搬到左侧的参考／制作单编辑表单、逐页审核表单、“请 Agent 复审本页”按钮和阶段条；助手检查结论直接回到对话，最终整套交付只需一次真实用户决定。通用文件工具按任务工作目录工作，不给每个业务场景新增按钮。

## 通用文件工具的复用与执行边界

核查已安装的 DSH 工具 types／README：`dsh-tools` 提供 defineTool 的 schema、执行、渲染与注册；`dsh-skill-filesystem` 提供技能目录，不是业务文件处理器；`dsh-attachment-local` 提供附件字节生命周期。其依赖中已有 `@deepseek-ai/libreoffice-kit@0.1.5` 和对应平台引擎，复用其转换／公式重算能力。结构化 Word／Excel 数据使用锁定的 python-docx／openpyxl；PDF、图片、压缩包继续复用已有 PDF.js、cleaner OCR、sharp 和 fflate。

文件工具从任务已冻结且核验 SHA 的来源导入工作目录；产物回传为带 SHA 的下载链接，更新文件后旧链接失效。原件不覆盖。常用清洗、筛选、去重、照片匹配和批量生成由简单 Python／JS 完成，不为每个业务场景增加专用按钮。

脚本按用户授权的受信本机代码执行，具有当前系统用户权限；cwd、环境白名单、超时、输出截断和常见密钥脱敏是运行约束，不是 OS 安全沙箱。宿主在脚本前后核对 task.json 与持久模型配置哈希；改变控制记录时中止本轮并报告冲突，不据此继续生成、批准或导出，也不擅自覆盖回滚。此检查用于防误改，不宣称抵御恶意同权限代码。正常审批仍经真实用户入口及版本／SHA 合同，模型没有审批工具。

源码开发入口和运行包共用同一个 Python 准备器：OCR 与 Office 两组锁文件共同进入依赖检查及指纹，实际缺项才同步；按用户 2026-10-17 的补充决定，运行包首次启动单独检查并准备 Python 环境，源码入口仍复用现有准备流程。
