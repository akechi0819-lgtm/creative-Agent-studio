本轮从 `391b955` 建立独立工作树 `p5-general`。开工时公司目录存在大量非本轮未提交改动，已记录逐文件 SHA 和 diff 基线到本机忽略证据目录；P5 改动迁移后，原公司目录基线文件 SHA 全部一致。公司分发分支与现网不作为本阶段目标，不整树提交或推送。

P4 启动准备复用修正线程已空闲，复用其提交，不重复重写。该报告最新记录了 OCR 使用系统 Python 与旧缓存补回可用环境，不能说找回旧虚拟环境原件。本轮不运行真实根 prepare／安装；开发依赖使用现有 node_modules 只读链接，分发必须用独立准备的实际文件，不能把这些链接带入包。

参考任务只读了解了 Excel 名单与照片匹配、筛选、去重、样张确认、脚本排版、批量图、工作簿与 ZIP 需求；未读取其用户文件或重放任务，未发出付费调用。

## 设计取舍

沿用现有鲸鱼助手、双栏工作台、字体与色彩。左栏以自然对话和必要的短方案卡为主，右栏直接展示方案、成品、对照与下载。根据用户现场反馈，删除搬到左侧的参考／制作单编辑表单、逐页审核表单、“请 Agent 复审本页”按钮和阶段条；助手检查结论直接回到对话，最终整套交付只需一次真实用户决定。通用文件工具按任务工作目录工作，不给每个业务场景新增按钮。

确认采用两条等价入口：左侧明确动作、或对实际展示版本的明确文本。宿主绑定 revision／sheetVersion 处理人工确认，模型没有批准工具。自然语言参考讨论先生成可见参考方案；方案本身不改人工决定。修改任务后旧方案和旧文本确认失效。制作单一次确认直接调用现有执行器，未知请求与失败重试继续遵守原幂等约束。

## 通用文件工具的复用与执行边界

核查已安装的 DSH 工具 types／README：`dsh-tools` 提供 defineTool 的 schema、执行、渲染与注册；`dsh-skill-filesystem` 提供技能目录，不是业务文件处理器；`dsh-attachment-local` 提供附件字节生命周期。其依赖中已有 `@deepseek-ai/libreoffice-kit@0.1.5` 和对应平台引擎，复用其转换／公式重算能力。结构化 Word／Excel 数据使用锁定的 python-docx／openpyxl；PDF、图片、压缩包继续复用已有 PDF.js、cleaner OCR、sharp 和 fflate。

文件工具从任务已冻结且核验 SHA 的来源导入工作目录；产物回传为带 SHA 的下载链接，更新文件后旧链接失效。原件不覆盖。常用清洗、筛选、去重、照片匹配和批量生成由简单 Python／JS 完成，不为每个业务场景增加专用按钮。

脚本按用户授权的受信本机代码执行，具有当前系统用户权限；cwd、环境白名单、超时、输出截断和常见密钥脱敏是运行约束，不是 OS 安全沙箱。宿主在脚本前后核对 task.json 与持久模型配置哈希；改变控制记录时中止本轮并报告冲突，不据此继续生成、批准或导出，也不擅自覆盖回滚。此检查用于防误改，不宣称抵御恶意同权限代码。正常审批仍经真实用户入口及版本／SHA 合同，模型没有审批工具。

源码开发入口和运行包共用同一个 Python 准备器：OCR 与 Office 两组锁文件共同进入依赖检查及指纹，实际缺项才同步；不在用户首次双击运行包时安装这些包。


## 本轮交互纠正（2026-10-16）

用户指出“将右侧功能原样搬到左侧”并不等于简化，明确取消手机兼容目标。P5 定位为桌面本机工具，只验常见桌面窗口和面板收起，不再投入手机布局或列作验收项。Web 不要求用户管理复审流程；助手生成后读图结果回到对话，用户可直接提出修改或一次确认当前整套成品交付。底层按该真实决定记录绑定版本与 SHA 的人工状态，保留陈旧批准失效和导出前后新鲜性校验；Codex 的既有共享工具合同不改。

早期点验过 390px 布局，该探索结果不作为本批目标或完成项，最终预览与验证以桌面版精简界面为准。
