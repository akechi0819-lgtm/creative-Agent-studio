# 源码更新与运行核验

本文说明如何从当前 Creative Agent Studio 源码更新并确认实际运行的是预期程序目录和构建。启动器会把规范化源码目录、可用的 Git 提交、发行类型和运行输入摘要写入本地控制健康响应及 `web/runtime.json`。摘要覆盖启动器、服务端、工作台前端构建及随产品构建的 Canvas／模型插件输入；不读取 `node_modules`、用户任务或本地配置内容。

同一数据目录已有服务时，源码入口和随包 Release 入口都只有在运行实例的程序目录和构建摘要与当前入口一致时才会打开旧页面；Windows VBS 和 macOS App 菜单都经过 Release launcher。身份缺失或不一致会显示两边身份并拒绝复用。此检查不会停止服务、强杀进程或删除任何文件。`status` 会返回 `sourceIdentity`、`currentIdentity` 和 `identityMatches`，`doctor` 会同时显示程序目录、数据目录、运行状态和身份。

## 更新顺序

1. 在当前源码目录记录 `node scripts/launcher.mjs status` 和 `node scripts/launcher.mjs doctor` 的结果，并检查工作台、Canvas、模型插件以及图片／文件任务是否有在途操作。等待操作完成后再继续；不要在任务进行时切换源码。
2. 从要更新的项目目录执行 `node scripts/launcher.mjs stop`，让工作台和本产品管理的服务正常退出。再运行 `node scripts/launcher.mjs status` 与 `node scripts/launcher.mjs doctor`，确认工作台已停止且没有待处理的写入者。
3. 停止后将当前配置与任务数据备份到源码目录以外的位置：

   ```sh
   node scripts/launcher.mjs backup --destination "/安全位置/Creative Agent Studio 更新前备份"
   ```

   备份可能包含本机配置与密钥，只保存在私有位置。确认命令返回成功并检查备份清单；不要把备份放进 Git 仓库或分发包。
4. 检查源码分支和本地修改，再获取与产品匹配的目标分支信息：

   ```sh
   git status --short --branch
   git diff --stat
   git diff --cached --stat
   git fetch origin
   ```

   先确认目标分支与当前产品一致，再只执行对应的比较命令：个人版／通用版使用 `git log --oneline --left-right HEAD...origin/main`；公司版使用 `git log --oneline --left-right HEAD...origin/codex/company-edition`。提交本地改动到本地备份分支，或将需要保留的改动（包含未跟踪文件）复制到仓库外的私有备份；审查后再决定如何合入。不要用 `git pull`、`git reset`、`git clean` 或覆盖式 checkout 丢弃本地修改。
5. 在确认本地修改已保护且目标分支内容已审阅后，切换／合入已获取的目标分支。运行准备命令验证依赖并构建受源码输入影响的产物：

   ```sh
   node scripts/launcher.mjs prepare
   ```

   依赖或构建失败时先处理错误，不要启动旧构建。`start` 也会执行准备检查，但这里先显式准备便于确认构建结果。
6. 启动当前源码并核对控制身份：

   ```sh
   node scripts/launcher.mjs start --no-open
   node scripts/launcher.mjs status
   ```

   `status` 必须返回 `running: true`、`identityMatches: true`，且 `currentIdentity` 与 `sourceIdentity` 的 `sourceDirectory`、`distribution` 和 `buildFingerprint` 一致。提交号用于定位源码；本地未提交更改由构建摘要识别。
7. 若更新前的旧服务仍在运行，`start` 会报告运行实例与当前入口身份并拒绝复用。先确认旧工作台没有在途作业，再从当前项目目录执行 `node scripts/launcher.mjs stop`；已打包的 Windows 入口再次打开 `Start.vbs` 并选择“停止工作台”，macOS App 菜单选择“停止工作台”。等待 `status` 显示停止，完成更新和构建后重新启动。停止通过本机认证控制接口完成，不依赖 PID 强杀。
8. 现场验收必须从日常使用的 Windows `Start.vbs`／桌面快捷方式或 macOS App 入口启动新版本，并再次核对 `identityMatches: true`。旧 p5.1.3 快捷方式可能仍指向旧程序目录；新版本代码无法拦截旧启动器自己启动的进程，因此要检查快捷方式属性中的目标路径和“起始位置”，并检查桌面、开始菜单、任务栏及下载目录中本产品旧入口／旧安装包，确认日常入口全部指向唯一的新安装目录。
9. 新版本安装、启动、配置与任务读取验收通过后，按内测 C 端交付要求删除旧快捷方式、旧程序目录和已确认属于本产品的旧下载包，只保留一份有效安装目录。删除前逐一核对绝对路径，确认目标不是新安装目录，不是任何共享目录、数据目录或其父子目录；检查符号链接／junction，不沿链接进入用户数据；检查旧程序目录内容，将发现的用户原件先移出并核对私有数据备份及任务/API 配置仍在稳定数据目录。任何路径或内容无法确认时停止清理，不做删除。旧可运行程序不作为归档副本保留；任务、API 配置、原件和私有数据备份继续保留。
