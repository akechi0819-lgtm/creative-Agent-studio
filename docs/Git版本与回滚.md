# Git版本与回滚

## 当前分支

- `main`：个人版源码与文档，GitHub默认分支。
- `codex/company-edition`：公司版，共享个人版修复，保留Teedy／远端Canvas和Company数据目录差异。

临时阶段分支在整合后归档或删除；不把本地旧历史、备份stash或旧标签推到公开仓库。项目收尾记录见 [项目收尾](项目收尾.md)。

## 更新和回退

更新前停止对应数据目录的服务并备份用户数据，再获取对应分支。Git保护源码，不代替任务／素材／配置备份；回退源码不会恢复数据格式或撤销已产生的图片。

查看当前提交与历史：

```sh
git status
git log --oneline -10
```

排查旧版本时，用日志里实际存在的提交创建独立检出，避免重置正在使用的目录：

```sh
git worktree add --detach ../studio-inspect <实际提交号>
```

旧版本运行需按其锁文件准备依赖，并设置独立 `STUDIO_DATA_DIR`，不能与新版本同时写真实用户数据。不要对当前目录执行破坏性的 `reset --hard` 或 `clean -fdx`。

## 保存范围

源码、锁文件、公开说明和必要的合成测试夹具进入Git。Node依赖、Python虚拟环境、构建产物、运行状态、历史验收原件、用户任务与API配置不进入版本库；唯一已审核的P0测试图片按既有例外保留。

源码更新、平台候选包和正式Release是不同动作；当前可下载件与验证范围以README和工程进度为准。不要推断旧本地P3标签存在于公开仓库，也不要使用 `git push --all` 或 `--tags` 同步阶段备份。
