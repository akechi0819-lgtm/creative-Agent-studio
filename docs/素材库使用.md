# 本地素材总库使用说明

素材库把用户提交的正文和原件保存在本机。导入不会自动清洗或入库；人工点击清洗后，素材进入待复核状态，只有人工确认的版本才会进入 Agent 默认检索和任务引用。标签由用户自由编写，没有固定分类表。

## 存储位置与备份

默认数据目录复用 `src/canvas/client.mjs` 的 `dataRoot()`；设置 `STUDIO_DATA_DIR` 可指定其他目录。素材元数据、版本历史和原件位于该目录下的 `assets/`，标签列表可由素材元数据重建。运行数据不写进项目仓库；项目源码目录不能作为素材数据目录。

备份时保留应用数据目录中的 `assets/`，以及任务和 DNA 的用户数据目录。不要把 Canvas 实例文件、模型凭据或其他 credentials 放入素材库、DNA、任务证据或备份包。原件导入时会扫描一部分常见凭据格式并拒绝疑似凭据文件；这不是通用的内容审查，仍应避免提交秘密信息。素材库文件以私有权限创建，读取和快照会校验原件 SHA-256。

## 状态与操作

流程是：

1. `importAsset(...)` 导入标题、正文、来源 metadata、自由标签和按顺序排列的原件，状态为 `staged`。
2. 人工点击清洗，调用 `cleanAsset(...)`。清洗器抽取正文和附件文本，生成摘要与自由标签建议；不会覆盖人工标题。
3. 清洗成功后状态为 `needs_review`。人工可以查看原件、微调正文/摘要/标签，再确认入库。若某字段经人工修改，后续重洗不会静默覆盖该字段。
4. `confirmAsset(...)` 校验原件哈希并记录人工身份及说明，状态变为 `confirmed`，同时固化该版本的 metadata snapshot。
5. `queryAssets(...)` 默认只查 `confirmed`。管理端可明确传 `confirmedOnly: false` 检索待复核素材。只有 `confirmed` 可以通过 `snapshotAsset(...)` 供任务引用。

全局标签改名或删除如果会影响正在清洗的素材，整次操作在任何素材或标签目录写入前拒绝（`ERR_ASSET_TAG_CLEANING`），不会部分修改。等清洗结束后重新读取标签版本，再决定并执行操作；不需要额外编辑正文或调用进程恢复来解锁。

清洗在元数据锁外异步执行，完成时会再次核对版本号；若清洗期间发生编辑或其他状态变更，旧结果会丢弃并返回版本冲突，不覆盖新内容。配置缺失、取消和清洗失败分别显示为 `clean_config_missing`、`clean_cancelled`、`clean_failed`，均可读取状态后重试。配置缺失时不会发起网络请求。当前没有素材库 Web 配置界面；CLI 不应通过版本库 JSON 文件保存模型凭据。

## Node API

模块位于 `src/assets/library.mjs`，默认使用 `dataRoot()`，也可在 options 中传临时或隔离测试目录 `root`。

```js
import {
  importAsset, readAsset, listAssets, queryAssets,
  cleanAsset, recoverClean, editAsset, confirmAsset, deleteAsset,
  replaceAssetFiles, listTags, renameTag, deleteTag, snapshotAsset,
} from "../src/assets/library.mjs";
import { readConfig } from "../src/web/config.mjs";

const staged = await importAsset({
  title: "家长活动参考",
  body: "人工录入的说明，可留空",
  source: { kind: "user-provided", note: "来源说明及其他非敏感 metadata" },
  tags: ["阅读活动", "家长沟通"],
  files: [
    { path: "/本机路径/封面.png", name: "封面.png", mimeType: "image/png" },
    { path: "/本机路径/正文.pdf", name: "正文.pdf", mimeType: "application/pdf" },
  ],
});

// 生产调用读取 Studio 共享模型配置的基础 API 通道。
const textModelConfig = (await readConfig()).basic;

// 未提供配置时只记录缺配置状态，不调用模型；仅 needs_review 才继续人工复核。
const reviewed = await cleanAsset(staged.id, {
  expectedRevision: staged.revision,
  config: textModelConfig,
});

if (reviewed.status === "needs_review") {
  const edited = await editAsset(reviewed.id, {
    body: "人工核对后的正文",
    summary: "人工调整后的摘要",
    tags: ["阅读活动", "线下分享"],
  }, { expectedRevision: reviewed.revision });

  const confirmed = await confirmAsset(edited.id, {
    by: "实际人工姓名或身份",
    note: "已核对原件、正文、摘要和标签",
  }, { expectedRevision: edited.revision });

  const sourceSnapshot = await snapshotAsset(confirmed.id);
  // sourceSnapshot.files 含经 SHA 校验的绝对 path、relativePath、name、order、sha256。
}
```

API 签名和用途：

| API | 用途 |
| --- | --- |
| `importAsset(payload, {root})` | 导入有序原件，返回 `staged` 记录。`files` 可为空；每项至少提供本机 `path`。 |
| `readAsset(id, {root})` | 读取当前完整记录、版本历史并校验当前原件。 |
| `listAssets(filters, {root})` | 管理列表，可按 `status`、`tags`、`tagMode`、`includeDeleted` 和分页过滤。 |
| `queryAssets(filters, {root})` | 检索正文、摘要、来源和文件提取文本；支持 `query`、自由标签、`tagMode: "all" \| "any"`。默认只返回已确认素材。 |
| `cleanAsset(id, {expectedRevision, config, signal, cleaner, root})` | 显式清洗。测试可注入 `cleaner` 函数或 `{cleanMaterial}`；生产默认使用 `src/assets/cleaner.mjs`。 |
| `recoverClean(id, {deadPid, expectedRevision, root})` | 恢复进程中断的清洗，只接受与 `cleaningJob.pid` 相同且当前已退出的进程；将状态标记为 `clean_failed`，不重放请求。 |
| `editAsset(id, payload, {expectedRevision, root})` | 编辑 `title/body/summary/tags/source`；只接受提供的字段。待清洗或失败状态保持原状态。 |
| `confirmAsset(id, {by,note}, {expectedRevision, root})` | 确认 `needs_review` 版本并生成已确认快照。`by` 是记录字段，不是身份认证；CLI 中填写姓名也不构成授权验证。 |
| `replaceAssetFiles(id, files, {expectedRevision, root})` | 更新原件及顺序，保留旧原件用于版本历史；撤销当前确认、清洗提取和确认快照，回到 `staged`，需要重新清洗和确认。 |
| `deleteAsset(id, {expectedRevision, root})` | 软删除，默认列表与 Agent 检索隐藏记录，原件和历史保留。当前没有永久清除/恢复命令。 |
| `listTags({root})` | 取得去重自由标签及其 revision。 |
| `renameTag(tag,newTag,{expectedRevision,root})` / `deleteTag(tag,{expectedRevision,root})` | 对所有关联素材改名或移除关联；会为受影响素材增加 revision/history，删除标签不会删除素材。 |
| `snapshotAsset(id, {root})` | 只对 `confirmed` 素材返回完整 metadata 版本和经过 SHA 校验的原件路径。返回自包含的 `id/revision/title/body/summary/tags/source/confirmedAt` 与 `files`；调用方应把原件复制到任务目录并再次核验 SHA，之后任务引用独立于总库后续修改。 |

所有写操作均要求调用方提供从最新 `readAsset` 或 `listTags` 读取的 `expectedRevision`。写入使用跨进程锁和原子 JSON 替换；revision 过期会拒绝写入并要求重新读取。每次状态修改都会保存前一版本到 metadata 的 `history`。

## CLI

命令行采用 `@payload.json` 输入，路径相对当前工作目录解析。写操作 payload 必须带最新的 `expectedRevision`。例如：

```json
{
  "title": "家长活动参考",
  "body": "",
  "source": { "kind": "user-provided", "note": "用户提交" },
  "tags": ["阅读活动", "家长沟通"],
  "files": [
    { "path": "/本机路径/封面.png", "name": "封面.png" },
    { "path": "/本机路径/正文.pdf", "name": "正文.pdf" }
  ]
}
```

保存为本地临时的 `import.json` 后执行：

```sh
node scripts/assets.mjs import @/本机路径/import.json
node scripts/assets.mjs list
node scripts/assets.mjs show ASSET_ID
node scripts/assets.mjs clean ASSET_ID @/本机路径/clean.json
node scripts/assets.mjs recover-clean @/本机路径/recover.json
node scripts/assets.mjs edit ASSET_ID @/本机路径/edit.json
node scripts/assets.mjs confirm ASSET_ID @/本机路径/confirm.json
node scripts/assets.mjs snapshot ASSET_ID
```

`clean.json` 只需提供最新的 `expectedRevision`，不要放 `config` 或凭据。`scripts/assets.mjs clean` 与 `scripts/clean-materials.mjs` 都从 Studio 私有配置读取基础 API；不再读取 `STUDIO_TEXT_*` 环境变量。`STUDIO_DATA_DIR` 只用于选择隔离的数据根目录，不传模型地址、模型名或密钥。空的基础 API 配置会显示 `clean_config_missing`，不会发起请求，也不会补默认服务地址。不要把凭据写入仓库文件或素材内容。`confirm.json` 的 `by`、`note` 是人为填写的记录，CLI 不验证操作者身份。

只有进程意外退出后，才使用 `recover-clean`；payload 形如 `{"id":"ASSET_ID","deadPid":1234,"expectedRevision":2}`。`deadPid` 必须来自最新 `show` 返回的 `cleaningJob.pid`，并且该进程必须已经退出。命令只标记中断和解除卡住状态，不会自动重发清洗请求。

其他命令包括 `query @filters.json`、`replace-files ASSET_ID @payload.json`、`delete ASSET_ID @payload.json`、`tags`、`tag-rename @payload.json` 和 `tag-delete @payload.json`。用 `node scripts/assets.mjs` 可查看参数格式。

## 当前限制

- 原件单个最大 100 MB，每条素材最多 100 个文件；当前清洗器支持 PDF、PNG/JPEG/WEBP/BMP 图片及 UTF-8 TXT/MD。扫描件 OCR 依赖本机独立 OCR 环境；清洗服务配置后会调用配置的模型服务。
- 正文清洗结果上限为 200,000 字符，摘要上限为 10,000 字符；超限会显式失败，不静默截断。文件提取结果会保存在素材记录中并参与检索。
- 检索实时扫描素材 JSON，没有单独索引；规模很大时尚未做性能优化。历史版本随素材记录增长，目前没有历史压缩或原件硬删除。
- 当前只有 Node API 和 CLI，没有素材库 Web UI，也不负责任务层的来源复制；`snapshotAsset` 供任务集成层复制原件并记录来源版本。

Agent 检索先查看实际标签列表，再组合已有标签；不臆造固定业务标签。主题不明确时先用关键词查正文和摘要，再按候选的标签筛选。素材入库确认不等于某项创作任务的保留决定。
