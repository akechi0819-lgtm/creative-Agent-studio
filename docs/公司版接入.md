# 公司版接入

2026-10-16。分支 `codex/company-edition`，基线为干净公开分支 `codex/public-release` 的 `4ae7f00`；公司施工在独立工作区完成，不混入并行进行的启动依赖复用改造。公司版采用员工本机运行、现有远端 Teedy 与新版 Canvas，不建设集中多用户服务。用户已补充决定：公司版按新版 Canvas 协议实现，旧公司远端 Canvas 由用户更新，不做旧协议适配。

## 与通用版的区别

| 模块 | 公司版行为 |
| --- | --- |
| Web／DSH 与 Codex | 继续共用任务核心；Codex 不启动 DSH |
| 素材 | 默认检索公司 Teedy；本机素材另列，不自动替代 |
| 人工保留 | 原件下载及任务快照在保留时发生，保留前只查候选与预览 |
| Canvas | 连接本人本机工具桥接和远端画布；不启动或停止旧桥接、旧站点 |
| 数据 | 默认独立 Company 数据目录；备份、更新使用同一公司目录 |
| 模型与品牌 | 基础模型继续本机配置；远端画布模型不被公司版保存操作覆盖；DNA 显式启用 |

## 首次使用

使用原有 Mac／Windows 薄入口准备依赖并启动公司分支，默认打开本机 4311。公司数据默认位于 macOS `~/Library/Application Support/Creative Agent Studio Company`、Windows `%LOCALAPPDATA%/Creative Agent Studio Company`、Linux `$XDG_DATA_HOME/creative-agent-studio-company`（未设置时为 `~/.local/share/creative-agent-studio-company`）。`STUDIO_DATA_DIR` 仍可显式指定；并行试用应使用独立目录，不指向个人版现存数据。

进入“公司连接”，填写个人 Teedy HTTPS 地址、账号和密码，以及新版远端画布的 HTTPS 站点地址。配置写入公司数据目录 `config/company.json`，普通接口不返回密码或私有连接密钥。空密码只在同一服务与账号下保留已保存值，更换服务或账号需提供对应新密码。不要把真实配置作为 payload 示例、日志或源码提交。

在任务中点击“打开 Canvas”，公司版自动准备本任务的纯工具桥接、独立端口、连接密钥和远端画布，`taskId` 同时作为远端项目 ID。首次打开通过 60 秒单次票据交接，页面取到内存连接凭据后立即删除地址栏中的票据；不会把 token 存入浏览器持久化。任务画布相互隔离，多个标签页目标不明确时会提示关闭多余连接。刷新后可从任务重新打开以取得新票据。普通同事无需手填目标 ID 或启动第二终端。

生图模型由使用者在远端 Canvas 本人的浏览器中配置并保存在该浏览器本地；静态包不带 API Key，也不会把配置同步给其他员工。公司版只读取远端当前模型；工作台本地保存图片配置不会覆盖远端模型。基础模型仍在工作台“模型与服务”中配置。

在素材页或任务参考页检索公司库。标签仅按明确范围输入；每个必需条件独占一行，行内 `|` 为备选，行间全部须命中。没有结果不会自动删条件。任务搜索将候选列入待选区；保留后下载本次原件（单文件 80 MiB、单篇最多 100 附件且合计 250 MiB），正文（最多 500,000 字符，超限拒绝保留）、附件顺序及 SHA-256 固定到任务；排除不下载原件。后续制作单、成图审核及最终批准继续按既有版本合同执行。

CLI 入口为 `node scripts/company.mjs`（`canvas-check TASK_ID` 检查特定任务），配置输入使用仓库外的 `@payload.json`。不重新运行旧安装器覆盖同事全局 MCP，也不读取或复制已有员工凭据。

## 远端 Canvas 协议核对

旧工作台固定使用 `@basketikun/canvas-agent@0.6.0`。本轮只读取其 npm 发布包源码，未启动其 Agent：

- `dist/canvas/session.js` 的健康结果含 `hasCanvas/clients/protocolVersion`，没有新版目标列表。
- `dist/server/http.js` 的 `/api/tools` 只传递 `name/input`；请求中的 `projectId/clientId` 没有参与路由。
- 旧执行器只证明活动画布的节点、连线与生图链路；不能由此证明新版原图读取、图片导入、机械工具、任务隔离和版本回收都可用。

公司版连接会明确诊断目标合同；不伪造本地实例身份、不把仅能返回 200 视为完整可用。不符合新版目标合同的旧桥接不会收到写操作。本分支只支持新版明确目标协议，提供独立公司工具桥接；公司旧远端 Canvas 由用户更新。升级后的网页必须包含本仓库的原图读取、导入及机械工具，不能只升级上游版本号。旧桥接不作为可运行的兼容路径。

## 原挂靠保护

旧项目 `docs/status.md` 记录：Teedy HTTPS 由 Canvas 的 Caddy 承载，曾因 Canvas 重建遗漏 Teedy 站点和容器网络而失效。当前公司版施工不修改该 Caddy 配置、Compose、Teedy 数据卷、ACL 或旧 Canvas。任何后续服务器发布必须核对两处站点及外部网络；回滚新版不能回滚公司素材库数据。

## 验证与未完成范围

本机源码与隔离自检已通过（266 项完整测试、11 项图片样例及公司／远端真实浏览器），详见 [公司版自检](公司版自检.md)。新测试使用虚构服务、合成附件和独立数据根；不连接付费模型，不重放历史任务。源码合同、浏览器、真实 Teedy 个人账号、真实远端 Canvas、两名员工灰测分别记录，不能互相替代。当前远端实际版本、员工账号联通与双人灰测尚未验证。


## 用户更新远端 Canvas

先运行 `node scripts/build-company-canvas.mjs`，得到 `.studio-runtime/company-canvas/company-canvas-remote.zip`。该包从当前固定源码构建，专为 HTTPS 远端站点使用浏览器 IndexedDB，不依赖 P4 本机的 `/__studio/storage` 或 `/__studio/session`。包内 `README.md` 给出静态根目录、SPA 路由回退及模型 API 跨域要求；不携带密钥或公司素材。

更新由用户负责。本轮不改服务器，旧 Teedy 与 Canvas 的 Caddy 站点、外部容器网络和数据卷应保留。该包只提供前端，模型服务或代理继续使用原配置；不包含多人服务端数据库，换浏览器或 Origin 后画布数据不共享。生图 API 配置保存在本人浏览器的本地存储中，不能把共用浏览器配置文件视作员工间隔离。员工任务已回收的图片、版本和导出仍在本机公司数据目录。
