## 交付能力

- macOS `Start.command` 和 Windows `Start.cmd` 共用准备器与维护逻辑。优先复用合格 Node，否则下载校验固定官方运行时；安装四套锁定 npm 依赖，构建工作台、Canvas 与 DSH 客户端，准备私有 Python／OCR 环境。源码指纹不变时跳过准备。
- 首次配置基础／生图 API；动态端口、重复启动复用、Canvas／模型插件启停，以及异常退出后的残留服务诊断。停止通过本机身份校验，不按猜测 PID 强杀。
- 中文维护菜单与命令入口：停止、备份、恢复、更新和诊断。更新针对当前已取得的源码先备份再重建，不自动选择或拉取远端分支。
- 备份逐文件 SHA-256 校验，恢复先完整校验并保留恢复前数据。任务 Canvas 状态与原图新增本机持久化，纳入备份；旧浏览器 IndexedDB、个人浏览器资料和全局客户端配置不迁移。
- 区域检测使用跨平台本地 OpenCV、Tesseract 中英文离线模型，替换 Swift／Vision。范围是二维码、文字行和矩形几何定位；一维条码不在本次实现范围。原有浏览器裁切、分割、拼贴与合成继续使用原像素路径。选型与预设精度门槛见 [区域检测](P4区域检测.md)。
- 公开源码采用清理后的干净根提交，本机 P3 回滚历史和标签保留。Windows Actions 在真 runner 执行安装、构建、OCR、单元测试、区域样例与真实浏览器回归。

普通使用和维护方法见 [本地Web交付](本地Web交付.md)，源码回滚见 [Git版本与回滚](Git版本与回滚.md)。

## 本轮发现与修正

真 Windows runner 已暴露并修正两项入口问题：workflow 的 job 环境表达式不能使用 `runner` 上下文，Windows PowerShell 5 调用 Node `-e` 时会丢失内部双引号。后续运行通过入口探测后，进一步发现旧 Canvas 锁文件只带 macOS 可选二进制，导致 esbuild 向上解析错误版本；已用 npm 官方 v1→v3 转换补齐跨平台可选包和 integrity，保留既有版本；本机及 Windows x64／arm64 目标安装验证均通过。首次本机私有 Python 准备也发现 uv 管理模式参数与环境变量冲突，已删除重复环境设置。另发现 Windows Git 默认换行会改变固定上游文件的 SHA-256，现用项目 `.gitattributes` 固定文本 LF、`.cmd` CRLF，不修改全局 Git 配置，也不放宽哈希校验。无系统 Node 分支又暴露了传入根路径尾反斜杠的引号问题，薄入口已修正；PowerShell 模块加载差异导致 `Get-FileHash` 不可用，改用 .NET SHA-256 和 ZipFile 完成校验、解压，固定期望哈希与解压前严格比较不变。重开浏览器验证发现 Canvas 恢复前过早报告就绪，已改为当前项目节点恢复后才开放工具，并加入延迟存储读取回归。Windows 全量回归还发现目录锁冲突返回 `EPERM`，已仅在目标确为锁目录时转换为任务已锁定；无锁或非目录目标保留原权限错误，新增定向并发回归。上述失败保留为施工记录，不计为平台通过。

Windows 最终完整日志与 run 元数据保存在 `docs/evidence/p4/windows-final.log` 和 `windows-final.json`；云端链接可直接复查。

本机最终证据位于忽略目录 `docs/evidence/p4/`：`node-tests-final.log`、`images-final.log`、`python-final.log`、`service-final.log`；维护与恢复证据为 `launcher-maintenance.log`、`maintenance-restore-verification.json`、`update-local.log`。这些是本机施工记录，公开仓库只包含源码和说明。
