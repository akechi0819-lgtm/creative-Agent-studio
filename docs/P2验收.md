## 本阶段给产品补上什么

素材进入同一总库，AI 根据内容生成自由标签；用户可以修改正文、摘要与标签，显式确认后才进入 Agent 默认检索。参考旧本机小红书清洗脚本的正文＋有序图片 OCR→模型摘要与标签处理，新项目提供共享 Node 模块、CLI 与独立 Python OCR 环境。DNA 是默认关闭、内容为空的全局提示词，有可选模板与显式保存入口。它们供 Codex 和未来 DSH 适配共用，Canvas 继续只绘图。

完整 Web 拖拽上传、点击 AI 清洗、标签微调与确认按钮属于 P3；P2 已提供各步骤对应的 API、状态和 CLI，不把命令行称作普通用户完整界面。

## 已实现范围

- `src/assets/library.mjs`：多附件暂存、显式清洗、待复核、人工修改与确认、标签列表及全局改名/删除、关键词和标签 all/any 检索、原件替换、软删除、版本历史、哈希校验。未确认素材不进入 Agent 默认检索。
- `src/assets/cleaner.mjs` 与 `scripts/clean-materials.mjs`：完整正文和有序原件，UTF-8 TXT/MD、PNG/JPEG/WebP/BMP、PDF 全页文字与 OCR，模型生成结构化摘要和自由标签。配置默认空白，不读取旧服务。接受完整 JSON 或单个 JSON 代码块，拒绝截断、缺字段及混有其他说明的输出。
- `scripts/ocr_materials.py`：独立 RapidOCR；PDF 每页识别并核对页数，无字图片保留 `no_text` 状态，不冒充识别到正文。超时与取消可见，不返回部分结果冒充成功。
- 跨进程锁和版本比较阻止过期清洗覆盖人工修改；手工字段不会被重洗覆盖。中断后 `recover-clean` 核实原 PID 已退出，恢复失败状态但不重放请求。
- `src/dna/profile.mjs` 与 `scripts/dna.mjs`：默认关闭的全局提示词、示例模板、人工显式保存、历史版本、过期拒绝。任务保存生效内容；全局变化不修改旧任务。
- `studio apply-dna` 显式应用新版后使旧确认失效；`studio set-asset-sources` 保存查看过的素材版本、借鉴用途、事实边界及任务自己的原件。后续库变化不改任务证据，导出核验并包含来源原件。

## 用户指定的真实批次

用户直接指定 `RAG-Yuki/inputs/留学预备/青少官号小红书笔记` 并要求选二三十篇清洗入库。实际目录只有 13 个图文文件夹，因此取全量 13 篇，共 85 个支持格式附件，其中 1 份 PDF 共 6 页。每篇作为一条历史图文，保留附件顺序和来源；没有当作独立 Logo/品牌素材分类。

原清洗模型配置只读可取，但实际 HTTP 401，未用它完成清洗入库。用户随后明确授权使用此前测试的 Grok 4.7 配置；公开 models 与最小 chat 均为 200，请求名 `grok-4.7`、连接探测返回名 `grok-4.7-build`。仅本次进程读取既有客户端配置，不使用管理密钥，不启动 DSH，不改服务或新产品默认配置。

## 返工自验（2026-10-14）：标签与在途清洗冲突

独立验收发现的原问题及原反例保留在 [P2独立验收](P2独立验收.md)。本轮修复已完成并实施自验通过，**待独立复验**；不将原独立验收结论改判通过。

采用简单的整体拒绝策略：`renameTag` / `deleteTag` 在同一库写锁内读取全部受影响素材，若任一条正在清洗或仍持有清洗 Job，返回 `ERR_ASSET_TAG_CLEANING`，检查在标签目录刷新和任何素材更新之前。没有部分改名或删除，没有改变清洗版本，也不会造成旧清洗回写冲突后的状态卡住。CLI 提示等清洗结束后重新读取标签和素材，再操作。

新增四项无网络合同测试覆盖改名/删除分别与清洗成功/失败交错：夹具按实际目录读取顺序安排可编辑素材在前、清洗素材在后，并把标签目录指纹设为过期；拒绝后逐文件比较 metadata、标签目录字节及 revision 均不变。清洗完成或失败后 Job 均为空，失败可在同一存活进程中正常重试，无须额外编辑或 recover；结束后标签操作成功，下一次清洗保留人工改名/删除决定。
